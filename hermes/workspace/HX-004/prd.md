# PRD: HX-004 프런트엔드 주요 화면 document.scrollHeight 및 레이아웃 검증 및 개선

## 1. 배경과 문제 정의
현재 stock-coin-trade 프로젝트의 프런트엔드 주요 화면(index.html)의 레이아웃이 가이드와 완전히 일치하지 않아, document.scrollHeight가 window.innerHeight를 초과하는 경우가 발생하고 있습니다. 이로 인해 1920×1080 해상도에서 브라우저 세로 스크롤이 생기며, 사용자 경험이 저하되고 있습니다. 카드 컴포넌트의 높이, 내부 여백, 상단 바 및 사이드바 높이 등이 디자인 가이드와 맞지 않아 레이아웃 최적화가 필요합니다.

## 2. 목표 / 비목표
### 목표
- index.html 및 관련 CSS(style.css)에서 document.scrollHeight가 window.innerHeight를 초과하지 않도록 레이아웃을 조정한다.
- 1920×1080 뷰포트에서 세로 스크롤이 발생하지 않도록 CSS 및 DOM 구조를 개선한다.
- 카드 내부 여백, 폼 레이아웃, 사이드바 및 상단 바 높이를 디자인 가이드에 맞게 조정한다.
- 카드 컴포넌트 및 폼 레이아웃을 2~3열 또는 중앙 정렬로 재구성하여 화면 밀도를 높인다.
- QA 시 바닥에 80px 이상 빈 공간이 없도록 한다.

### 비목표
- 새로운 기능 추가나 백엔드 API 변경은 포함하지 않는다.
- 전면적인 UI/UX 리디자인은 이번 작업 범위에 포함하지 않는다.

## 3. 현재 구현 분석
- 주요 화면은 frontend/index.html 25~116줄에 카드 컴포넌트와 차트 섹션이 포함되어 있음.
- 카드들은 Tailwind CSS의 grid 시스템(grid-cols-1, md:grid-cols-2, xl:grid-cols-4 등)으로 1~4열 배치 중이며, 각 카드 내부는 padding과 margin으로 여백 조정 중.
- 상단 바 및 사이드바는 공통 셸로 구현되어 있으며, 사이드바 폭과 상단 바 높이는 디자인 가이드에 맞게 고정되어 있음.
- CSS는 frontend/css/style.css에 Tailwind CSS 기반으로 작성되어 있으며, 색상, 여백, 폰트 등 디자인 토큰이 변수로 정의되어 있음.
- 현재 document.scrollHeight 관련 직접적인 스크립트 조작은 없으며, 레이아웃 문제는 CSS와 DOM 구조 조정으로 해결해야 함.

## 4. 요구사항
- R-1: index.html 주요 화면의 document.scrollHeight가 window.innerHeight를 초과하지 않도록 레이아웃을 조정한다.
- R-2: 1920×1080 뷰포트에서 브라우저 세로 스크롤이 발생하지 않도록 CSS 및 DOM 구조를 개선한다.
- R-3: 카드 컴포넌트 내부 여백(padding), 폼 레이아웃, 사이드바 및 상단 바 높이를 디자인 가이드에 맞게 조정한다.
- R-4: 카드 레이아웃은 2~3열 또는 중앙 정렬로 구성하여 화면 밀도를 최적화한다.
- R-5: QA 시 바닥에 80px 이상 빈 공간이 없도록 한다.
- R-6: Tailwind CSS 유틸리티 클래스를 사용하여 스타일을 구현하며, 기존 CSS 변수와 토큰을 재사용한다.
- R-7: 변경 사항은 공통 셸 내에서 이루어져야 하며, 사이드바 트리거 버튼과 레이아웃 상태 유지 기능을 포함한다.
- R-8: QA 자동화 도구(hermes-fleet scripts/monitor.sh qa)를 통해 document.scrollHeight, window.innerHeight, 스크롤 발생 여부, 빈 공간 크기 등을 검증한다.

## 5. 수용 기준
- AC-1: 1920×1080 뷰포트에서 index.html의 document.scrollHeight가 window.innerHeight 이하임을 확인한다.
- AC-2: 브라우저 세로 스크롤이 발생하지 않으며, 가로 스크롤도 발생하지 않는다.
- AC-3: 카드 내부 여백, 폼 레이아웃, 사이드바 및 상단 바 높이가 디자인 가이드에 명시된 값과 일치한다.
- AC-4: 카드 레이아웃이 2~3열 또는 중앙 정렬로 구성되어 있으며, 카드 간격과 패딩이 가이드에 맞게 조정되었음을 확인한다.
- AC-5: 화면 바닥에 80px 이상 빈 공간이 없음을 QA 측정 도구로 검증한다.
- AC-6: Tailwind CSS를 사용하여 스타일이 구현되었고, 별도의 불필요한 CSS 파일 추가가 없으며, 기존 CSS 변수와 토큰을 재사용한다.
- AC-7: 공통 셸 내에 변경된 화면이 포함되어 있으며, 사이드바 트리거 버튼이 정상 작동한다.
- AC-8: hermes-fleet qa 스크립트 실행 시 레포트에 모든 체크 항목이 PASS로 기록된다.

## 7. 리스크와 열린 질문
- 리스크: 1920×1080 해상도 외 다른 해상도(1366~1920)에서 레이아웃이 깨질 가능성. 반응형 대응 필요성.
- 리스크: Tailwind CSS 유틸리티 클래스만으로 모든 레이아웃 문제를 해결하지 못할 경우, 기존 CSS 변수와 조화롭게 조정하는 데 추가 작업 필요.
- 질문: 카드 컴포넌트의 2~3열 배치 기준과 중앙 정렬 적용 여부에 대한 상세 가이드가 필요한가?
- 질문: QA 자동화 도구 hermes-fleet의 세부 측정 기준과 실패 시 대응 프로세스는 어떻게 되는가?
- 질문: 상단 바 및 사이드바 높이 조정 시 기존 공통 셸과의 호환성 문제는 없는가?
