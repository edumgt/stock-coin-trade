EC2 · SYSTEMD · FULL LOGICAL BACKUP

DB 백업 정책

EC2에서 실행 중인 MariaDB와 PostgreSQL의 모든 데이터베이스를 6시간마다 압축 SQL로 저장합니다. 각 파일은 SHA-256으로 무결성을 확인하고, 생성 후 72시간이 지난 백업은 자동 삭제합니다.

01

백업 방식

서비스 중단 없이 논리 백업을 만들고 압축·검증·보존 처리를 한 번에 수행합니다.

MariaDB

모든 DB 일관성 덤프

mariadb-dump --all-databases와 --single-transaction으로 테이블·트리거·이벤트·프로시저를 저장합니다.

PostgreSQL

역할과 모든 DB 덤프

pg_dumpall --clean --if-exists로 역할, 권한, 전체 데이터베이스를 복원 가능한 SQL로 저장합니다.

압축·검증

gzip + SHA-256

먼저 .partial에 기록하고 gzip -t가 성공한 뒤 최종 파일로 이동합니다. 체크섬 파일도 함께 만듭니다.

보존

72시간 후 삭제

find -mmin +4320 기준으로 SQL 압축 파일, 체크섬과 미완성 파일을 제거합니다.

범위: 현재 EC2의 crypto-mock-mariadb, crypto-mock-postgres(퀀트), pg-stock(OHLCV 원본) 전체입니다. Qdrant 인메모리 데이터와 Redis 세션은 이 SQL 백업 대상이 아닙니다.

03

실행 스크립트 핵심

실제 운영 파일의 핵심 명령입니다. 비밀번호는 명령행에 직접 쓰지 않습니다.

# MariaDB 전체 백업
docker exec crypto-mock-mariadb sh -ec '
  export MYSQL_PWD="$MARIADB_ROOT_PASSWORD"
  exec mariadb-dump -uroot --all-databases --single-transaction \
    --quick --routines --events --triggers --hex-blob
' | gzip -9 > mariadb_all_TIMESTAMP.sql.gz.partial

# PostgreSQL 역할 + 전체 DB 백업
docker exec crypto-mock-postgres sh -ec '
  exec pg_dumpall --clean --if-exists -U "$POSTGRES_USER"
' | gzip -9 > postgresql_all_TIMESTAMP.sql.gz.partial

# 3일(72시간) 초과 파일 삭제
find /var/backups/stock-coin-trade -type f -mmin +4320 -delete
04

운영 점검과 수동 실행

타이머, 최근 로그, 백업 파일과 체크섬을 순서대로 확인합니다.

# 다음 실행 시각과 마지막 실행 결과
sudo systemctl list-timers stock-coin-trade-db-backup.timer
sudo systemctl status stock-coin-trade-db-backup.timer

# 즉시 1회 실행 및 로그 확인
sudo systemctl start stock-coin-trade-db-backup.service
sudo journalctl -u stock-coin-trade-db-backup.service -n 100 --no-pager

# 생성 파일과 무결성 확인
sudo find /var/backups/stock-coin-trade -maxdepth 2 -type f -ls
cd /var/backups/stock-coin-trade/mariadb && sudo sha256sum -c *.sha256
cd /var/backups/stock-coin-trade/postgresql && sudo sha256sum -c *.sha256

이 정책은 EC2 로컬 EBS 장애까지 보호하지는 않습니다. 장기 보존 또는 인스턴스 장애 대비가 필요하면 암호화된 S3 버킷·수명주기 정책으로 복제하는 2차 백업을 추가해야 합니다.

05

복원 연습

운영 DB에 바로 덮어쓰지 말고 격리된 테스트 컨테이너에서 먼저 검증합니다.

  1. 복원할 파일의 sha256sum -c와 gzip -t를 먼저 통과시킵니다.
  2. 운영과 분리된 임시 MariaDB/PostgreSQL 컨테이너를 생성합니다.
  3. MariaDB는 gzip -dc FILE | mariadb -uroot, PostgreSQL은 gzip -dc FILE | psql -U ADMIN -d postgres 방식으로 복원합니다.
  4. 테이블 수·주요 행 수·로그인·조회 API를 점검한 뒤에만 운영 복원을 승인합니다.
