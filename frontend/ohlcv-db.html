DOCKER CLASS · OHLCV DB

docker-class 배치 파이프라인이 적재하는 종목별 과거 시세 DB

이 화면이 설명하는 PostgreSQL(pg-stock)은 /home/ubuntu/docker-class 학습 저장소의 cron 배치가 KOSPI·KOSDAQ 전 종목의 일봉 OHLCV를 수집해 쌓는 별도의 로컬 학습용 DB입니다. 이 앱은 집계 확인을 위해 읽기 전용으로만 조회하며, 실거래·모의투자 백엔드와는 데이터를 주고받지 않습니다. 퀀트 연구용 PostgreSQL(quant.html)과도 별개의 인스턴스입니다.

4단계 파이프라인

수집 → 3단계 동기화 → DB 적재 → 백업까지 전부 cron으로 자동화되어 있습니다.

1

수집 (매 1분)

FinanceDataReader로 KOSPI·KOSDAQ 전 종목(약 2,765개) 목록을 구하고, yfinance로 종목·연도별 OHLCV를 data-1/에 CSV로 저장합니다.

fetch_ohlcv_batch.sh → fetch_ohlcv.py
2

3단계 동기화

rsync --update로 data-1 → data-2(10초 간격) → data-3(1분 간격) 순으로 새 파일만 전달합니다. 3단계로 나눈 덕분에 수집 작업이 최종 적재 대상 폴더를 직접 건드리지 않습니다.

sync-loop-10s.sh · sync-data2-to-data3.sh
3

DB 적재 (매시 정각)

data-3/의 모든 CSV를 읽어 tickers·ohlcv 테이블에 적재합니다. PK (ticker_code, trade_date) + ON CONFLICT DO NOTHING이라 재실행해도 중복 없이 새 행만 들어갑니다.

load_data3_to_db.sh → load_data3_to_db.py
4

백업 (2시간마다)

실행 중인 pg-stock 컨테이너를 docker commit으로 스냅샷 떠서 Docker Hub로 push합니다. 트랜잭션 정합 백업이 아닌 crash-consistent 백업이라는 한계를 README에 명시해 두었습니다.

backup_pg_to_dockerhub.sh → edumgt/pg-stock-backup
01

테이블 구조 — 종목마다 테이블을 만들지 않는 이유

종목별로 테이블을 따로 만들면 수천 개 종목을 감당하기 어려워, 종목 마스터 1개 + 공용 시세 1개로 구성합니다.

tickers (종목 마스터)

ticker_code
종목 코드. PK. 예: 005930
name / market
종목명과 시장 구분(KOSPI 등). 적재 배치는 현재 코드만 채우고 나머지는 비워 둡니다.
created_at
처음 발견되어 등록된 시각.

ohlcv (전 종목 공용 시세)

ticker_code, trade_date
복합 PK. 한 종목의 하루치 캔들 1행.
open / high / low / close
시가·고가·저가·종가.
adj_close / volume
수정종가와 거래량.

인덱스 · 적재 방식

idx_ohlcv_trade_date
날짜 범위 조회 최적화용 보조 인덱스.
적재 스크립트
execute_values + ON CONFLICT (ticker_code, trade_date) DO NOTHING으로 idempotent하게 삽입.
ohlcv 예시 행 (003080, 2025-01-02) 003080 | 2025-01-02 | 2,490.0 | 2,495.0 | 2,470.0 | 2,490.0 | 2,315.59 | 7,549

CSV 원본 컬럼(Date, Open, High, Low, Close, Adj Close, Volume)은 yfinance 응답 그대로이며, 적재 스크립트가 trade_date/open/high/low/close/adj_close/volume으로 이름을 바꿔 넣습니다.

02

접속 · 운영 정보

이 DB는 docker-class 저장소를 클론한 로컬/사내 환경에서만 뜨는 컨테이너입니다.

실행 위치

docker-class/postgresql/docker-compose.yml → 컨테이너명 pg-stock, 이미지 postgres:latest. 호스트 127.0.0.1:5433으로만 노출되며 이 앱의 웹 서버·API와는 네트워크로 연결되어 있지 않습니다.

접속 계정

DB명 admin. 계정·비밀번호는 저장소에 커밋하지 않고 docker-class/postgresql/.env.example을 복사한 .env로 관리합니다. 운영자는 해당 README의 "접속 정보" 절을 참고하세요.

데이터 범위
