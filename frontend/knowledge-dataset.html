RAG · VECTOR DB

RAG 벡터 검색의 원리

벡터(Vector)와 행렬(Matrix)은 모두 숫자를 규칙적으로 배열하여 데이터를 표현하는 선형대수학의 기본 단위이지만, 차원 구조(수치 배열의 형태)와 용도에서 명확한 차이가 있습니다.

1. 핵심 차이 요약

구분벡터 (Vector)행렬 (Matrix)
차원 구조1차원 배열 (1행 n열 또는 m행 1열)2차원 배열 (m행 n열)
기하학적 의미공간 상의 한 점 또는 방향과 크기를 가진 화살표공간 전체를 변형시키는 선형 변환(Linear Transformation)
주요 역할상태, 위치, 특성(Feature) 값 등 데이터 개체 표현시스템, 관계, 데이터 또는 공간의 변환/회전/축소 표현
표기 예시 ⎡ x ⎤ v = ⎢ y ⎥ ⎣ z ⎦A = ⎡ a b ⎤ ⎣ c d ⎦

2. 세부 개념 및 비유

① 벡터 (Vector) — "데이터의 상태나 위치"

  • 개념: 숫자들을 1열로(가로 또는 세로) 길게 나열한 것입니다.
  • 비유: '한 사람의 건강 검진 결과'
    • [키, 체중, 혈압, 혈당] = [175, 70, 120, 90] 과 같이 1차원 데이터로 개체의 상태를 표현합니다.
  • AI/IT 분야 활용: 문장 임베딩(Sentence Embedding), 이미지 특징값(Feature Vector) 등 단일 데이터의 특성을 표현할 때 사용합니다.

② 행렬 (Matrix) — "데이터 간의 관계 또는 변환 규칙"

  • 개념: 숫자들을 격자 형태(행과 열의 2차원)로 나열한 것입니다.
  • 비유: '여러 사람의 건강 검진 데이터 표' 또는 '필터/렌즈'
    • 여러 명의 검진 결과를 행과 열로 정리한 데이터베이스 표가 될 수도 있고,
    • 특정 벡터에 행렬을 곱했을 때 그 벡터의 위치나 크기를 바꾸는 '변환 장치' 역할을 합니다.
  • AI/IT 분야 활용: 딥러닝의 가중치(Weights) 집합, 데이터 세트 전체 표현, 이미지 회전 및 3D 그래픽스 변환 등에 사용합니다.

3. 수량 체계에서의 확장 관점 (스칼라 → 텐서)

선형대수학 전체 맥락에서 보면 차원이 확장되는 단계로 이해하면 쉽습니다.

  1. 스칼라 (Scalar): 0차원 → 단일 숫자 (예: 5)
  2. 벡터 (Vector): 1차원 → 숫자의 1차원 배열 (예: [1, 2, 3])
  3. 행렬 (Matrix): 2차원 → 숫자의 2차원 격자 배열 (예: ⎡ 1 2 ⎤ ⎣ 3 4 ⎦)
  4. 텐서 (Tensor): 3차원 이상 → 행렬을 여러 겹으로 쌓은 고차원 배열 (예: RGB 이미지 데이터는 [너비 × 높이 × 3채널]의 3차원 텐서)
요약
• 벡터는 대상의 '상태'나 '특성'을 나타내는 1차원 데이터입니다.
• 행렬은 여러 벡터를 모아놓은 '데이터 집합'이거나, 벡터를 변형시키는 '변환 규칙(2차원)'입니다.

AI에서 사용하는 벡터 DB는 2차원/3차원의 '공간벡터'에 그치지 않고, 수십에서 수천 차원에 이르는 고차원 공간벡터(High-Dimensional Spatial Vector)를 다룹니다. 수학적으로 접근해 보면 다음과 같습니다.

1. 왜 고차원 공간벡터일까요?

  • 평면벡터 (2차원): (x, y)처럼 2개의 축으로 이루어진 벡터입니다.
  • 공간벡터 (3차원): (x, y, z)처럼 3개의 축으로 물리적 3차원 공간을 표현하는 벡터입니다.
  • AI의 벡터 (N차원 공간): AI 모델(LLM, 임베딩 모델 등)은 단어, 문장, 이미지 등의 의미(Semantic)를 표현하기 위해 수십~수천 개의 차원을 사용합니다.
    • 예: OpenAI text-embedding-3-small은 1,536차원, text-embedding-3-large는 3,072차원 공간벡터입니다.

즉, 우리가 눈으로 볼 수 있는 것은 3차원 공간까지지만, 수학적으로는 N차원 유클리드 공간(Euclidean Space) 상에 위치하는 공간벡터입니다.

2. 개념의 차이 한눈에 보기

구분평면 vector일반 공간 vectorAI 벡터 DB (Embedding)
차원 (Dimensions)2차원3차원N차원 (보통 384 ~ 3,072차원 이상)
표현 형태(x, y)(x, y, z)(v₁, v₂, v₃, …, vₙ)
주요 용도2D 그래픽, 단순 평면 운동3D 그래픽, 물리적 공간문장, 이미지, 음성 등의 의미적 맥락 표현
유사도 측정피타고라스 정리3D 거리 계산코사인 유사도, 내적(Dot Product) 등

3. AI는 왜 이런 고차원 공간을 쓸까요?

데이터의 복잡한 의미와 특징을 담기 위해서입니다. 예를 들어 "사과"라는 단어를 벡터 공간에 매핑할 때:

  • v₁ 축: 과일일 확률
  • v₂ 축: 빨간색일 확률
  • v₃ 축: IT 기업(Apple)일 확률
  • v₄ 축: 전자제품과 관련된 맥락...

이처럼 수많은 기획적 축(차원)을 가진 고차원 공간상의 한 점(Vector)으로 변환하여 저장합니다.

벡터 DB는 이 고차원 공간에서 "문맥이나 의미가 유사한 벡터들이 서로 가까운 위치에 모인다"는 성질을 이용해, 코사인 유사도(Cosine Similarity)나 유클리드 거리 등을 계산하여 가장 가까운 데이터를 찾아내는 역할을 합니다.

HNSW (Hierarchical Navigable Small World) 알고리즘은 수백~수천 차원의 공간벡터 중에서 내가 찾고자 하는 벡터와 가장 가까운 벡터(Nearest Neighbor)를 빛의 속도로 찾아내는 그래프 기반 알고리즘입니다.

차원이 높아질수록 모든 벡터와 하나씩 거리를 비교하는 방식(Linear Search)은 속도가 극도로 느려집니다. HNSW는 이 문제를 해결하기 위해 "Skiplist(건너뛰기 목록)의 계층 구조"와 "Small World(작은 세상) 그래프 효과"를 결합했습니다.

1. HNSW의 핵심 개념 2가지

① Small World Graph (작은 세상 그래프)

  • 내용: 케빈 베이컨의 6단계 법칙처럼, "몇 단계만 거치면 전체 네트워크의 누구에게나 도달할 수 있다"는 개념입니다.
  • 원리: 각 노드(벡터)는 가까운 이웃들과 밀접하게 연결되어 있으면서도, 일부 멀리 떨어진 노드와 연결되는 '지름길(Long-range link)'을 가지고 있습니다. 이를 통해 그래프 상에서 아주 멀리 떨어진 영역으로도 순식간에 이동할 수 있습니다.

② Hierarchical Structure (계층형 구조)

  • 내용: 네트워크의 연결 구조를 여러 레이어(Layer)로 쌓아 올려 탐색 속도를 극대화합니다.
  • 원리: KTX, 고속도로, 국도, 골목길의 관계와 같습니다.
    • 최상위 레이어 (Layer 2): 노드 수가 적고, 매우 긴 거리를 잇는 지름길로만 구성 (KTX)
    • 중간 레이어 (Layer 1): 노드 수가 중간 정도이며, 지역 간 이동 경로로 구성 (고속도로/국도)
    • 최하위 레이어 (Layer 0): 모든 벡터가 포함되어 있으며, 가장 가까운 이웃들끼리 밀접하게 연결 (골목길)

2. HNSW의 검색(Search) 작동 과정

검색 쿼리가 들어왔을 때, HNSW는 위에서 아래로 내려오는 탐색(Top-Down Search) 방식을 취합니다.

[Layer 2 - 최상위] (진입점) ─────────▶ (대략의 위치 근처 노드) │ (하향 이동) [Layer 1 - 중간] ────────────▶ (더 가까운 노드) │ (하향 이동) [Layer 0 - 최하위] ────────▶ [목표 노드 (가장 유사한 벡터)]
  1. 최상위 레이어 진입: 지정된 진입점(Entry Point)에서 시작합니다.
  2. 성긴 탐색 (Coarse Search): 성기게 연결된 상위 레이어에서 쿼리 벡터와 가장 가까운 노드를 향해 큰 폭으로 점프하며 이동합니다.
  3. 계층 하강: 현재 레이어에서 더 이상 가까워질 수 없는 지역 최적점(Local Minimum)에 도달하면, 바로 아래 레이어의 동일한 노드로 내려옵니다.
  4. 정밀 탐색 (Fine Search): 하위 레이어로 내려올수록 노드 밀도가 높아지므로 점점 더 미세하고 정확하게 목표 벡터에 접근합니다.
  5. 최하위 레이어(Layer 0) 도착: Layer 0에서 최종적으로 가장 가까운 K개의 벡터(k-NN)를 찾아 반환합니다.

3. HNSW가 빠른 이유 및 장단점

구분주요 특징
탐색 시간 복잡도O(log N) (모든 벡터를 다 비교할 필요 없이 대폭 줄어듦)
장점• 현존하는 ANN(Approximate Nearest Neighbor) 알고리즘 중 최고 수준의 검색 속도 및 높은 정확도(Recall) 제공
• 지속적인 데이터 추가(Insert) 시에도 그래프 업데이트가 비교적 용이
단점• 메모리(RAM) 사용량이 매우 큼 (각 노드 간의 연결 링크 정보를 메모리에 유지해야 함)
• 정확도와 속도 간의 트레이드오프(Trade-off) 존재

RAG(Retrieval-Augmented Generation, 검색 증강 생성) 시스템에서 벡터 DB가 핵심 엔진 역할을 하는 이유와 AI가 벡터를 생성하고 판단하는 원리를 3가지 단계로 나누어 설명합니다.

1. RAG에서 벡터 DB가 왜 중요한가?

기존의 키워드 검색 방식(예: SQL, ElasticSearch)과 AI의 문맥 이해 방식 간에는 큰 격차가 있습니다. 벡터 DB는 이 격차를 메워주는 "의미 기반 검색(Semantic Search)"을 가능하게 합니다.

① 키워드가 달라도 '의미'를 찾아냄

  • 기존 키워드 검색: "스마트폰 배터리 오래 쓰는 법"을 검색하면, 정확히 '스마트폰', '배터리'라는 단어가 포함된 문서만 찾아냅니다.
  • 벡터 DB (의미 검색): "휴대폰 전원 오래 유지하는 팁"처럼 단어가 전혀 달라도 같은 의미라는 것을 파악하여 관련 문서를 찾아냅니다.

② 환각(Hallucination) 현상 방지

LLM(대형 언어 모델)은 학습되지 않은 최신 정보나 기업 내부 데이터에 대해 거짓말을 할 수 있습니다. 벡터 DB는 기업 내부 문서들을 벡터 형태로 들고 있다가, 사용자의 질문과 가장 밀접하게 연관된 "정확한 출처 문서"를 빛의 속도로 찾아내 LLM에게 전달(Context)해 줍니다.

2. 벡터는 AI가 자동으로 판단해서 만드는가?

네, 맞습니다. 사람이 일일이 "사과는 과일이다", "사과는 빨갛다"라고 숫자를 입력하는 것이 아니라, 임베딩 모델(Embedding Model)이라는 특수한 AI가 자동으로 수치화(벡터화)합니다.

AI가 벡터를 판단하고 생성하는 과정은 다음과 같습니다.

[텍스트 문서 / 질문] │ ▼ [임베딩 AI 모델] (예: OpenAI text-embedding-3) │ (자동 변환) ▼ [고차원 공간의 좌표 (Vector)] [0.012, -0.043, 0.891, ..., 0.105]

① 수많은 문맥 데이터 사전 학습

임베딩 AI 모델은 수억 개의 문장과 단어 관계를 미리 학습한 상태입니다. 따라서 어떤 단어나 문장이 들어와도 그 단어가 가진 의미적 특징을 수백~수천 개의 차원(수치)으로 분해할 수 있습니다.

② 의미적 특징을 공간 좌표로 자동 매핑

예를 들어 text-embedding-3-small 모델은 문장이 들어오는 즉시 1,536개의 숫자로 이루어진 공간 좌표(Vector)로 바꾸어 버립니다.

  • "왕" → [0.23, 0.81, -0.12, ...]
  • "여왕" → [0.21, 0.85, -0.10, ...] (왕과 위치가 매우 가까움)
  • "자동차" → [-0.75, -0.42, 0.61, ...] (왕/여왕과 위치가 매우 멂)

③ 같은 텍스트는 항상 같은 벡터가 나올까?

text-embedding-3-small이라는 정확히 같은 모델을 사용하는 한 항상 100% 똑같은 1,536개의 숫자가 나옵니다. 언제, 어디서, 누가 호출하든 "사과"라는 같은 텍스트를 입력하면 이 모델은 토시 하나 틀리지 않고 똑같은 1,536차원의 벡터 좌표를 반환합니다.

예외적으로 숫자가 달라질 수 있는 딱 2가지 경우
기본적으로는 무조건 동일하지만, 실제 시스템 개발 시 아래의 2가지 상황에서는 수치가 달라질 수 있으니 주의해야 합니다.

  1. 입력 텍스트가 미세하게 다를 때 (공백, 대소문자 등)
    AI는 텍스트를 문자가 아닌 토큰(Token) 단위로 쪼개서 처리합니다. 사람이 보기엔 같아 보여도 미세한 차이가 있으면 완전히 다른 숫자가 나옵니다.
    • "사과" (공백 없음)
    • "사과 " (뒤에 띄어쓰기 한 칸 있음)
    • "Apple" vs "apple" (대소문자 차이)
    위의 예시들은 사람이 보기엔 같은 의미지만, 모델 입장에서는 다른 입력값으로 인지하여 서로 다른 1,536개의 숫자를 만들어냅니다.
  2. 차원 수(Dimensions) 축소 옵션을 사용했을 때
    text-embedding-3-small 모델은 차원 수를 줄일 수 있는 dimensions 파라미터 옵션을 공식 지원합니다.
    • 기본 호출: 1,536개 수치 생성
    • dimensions=512 옵션 지정 호출: 512개 수치 생성
    옵션을 다르게 주고 호출하면 차원 수가 달라지므로 수치 집합이 달라집니다. (단, 파라미터 설정을 고정해 두었다면 당연히 결과도 고정됩니다.)
결론적인 요약
RAG나 벡터 DB 시스템을 만들 때 text-embedding-3-small 모델로 고정하고, 입력 텍스트 전처리(공백 제거 등)만 동일하게 유지한다면 언제나 동일한 벡터값이 보장되므로 안심하고 검색 및 비교 연산에 사용해도 됩니다.

3. RAG와 벡터 DB의 전체 작동 원리

RAG가 실제로 구동되는 과정은 크게 [저장 단계]와 [검색 및 답변 단계]로 나뉩니다.

[저장 단계] 문서(PDF/TXT) ──(임베딩 AI)──▶ 벡터 변환 ──▶ 벡터 DB에 저장 [검색 및 답변 단계] 1. 사용자 질문 ──(임베딩 AI)──▶ 질문 벡터 변환 2. 질문 벡터 ──(의미 거리 비교)──▶ 벡터 DB에서 가장 가까운 문서 K개 추출 3. 추출된 문서 + 사용자 질문 ──▶ LLM 전달 ──▶ 최종 답변 생성
  1. 문서 벡터화 (저장): 사내 규정이나 제품 설명서 등 준비된 문서를 임베딩 AI로 전달하여 벡터 데이터로 만든 후 벡터 DB에 저장해 둡니다.
  2. 질문 벡터화: 사용자가 "연차 신청 어떻게 해?"라고 물어보면, 이 질문도 똑같이 임베딩 AI를 거쳐 질문 벡터 좌표로 만듭니다.
  3. 벡터 공간 검색 (Vector DB의 핵심): 벡터 DB는 질문 벡터 좌표 주변 가장 가까운 거리(코사인 유사도 등)에 모여있는 문서 벡터를 고속으로 탐색(HNSW 알고리즘 등 사용)합니다.
  4. LLM 조합 출력: 벡터 DB가 찾아낸 문서(예: "휴가 및 연차 사용 규정.pdf")의 실제 텍스트 내용을 질문과 함께 LLM에게 전달하여, LLM이 이를 바탕으로 자연스러운 답변을 생성합니다.
요약
• 벡터 DB가 중요한 이유: 단어가 정확히 일치하지 않아도 문맥과 의미가 통하는 문서를 고속으로 검색해 LLM에 제공하기 위함입니다.
• AI의 벡터 판단 원리: 임베딩 AI 모델이 문장의 다차원적 의미를 수천 개의 숫자 좌표로 자동 변환하며, 유사한 의미일수록 공간상에서 가까운 위치에 배치되도록 판단합니다.

HNSW 알고리즘을 지원하여 고차원 벡터를 빠르게 검색하는 대표적인 Vector DB 4종(Pinecone, Milvus, Qdrant, Chroma)의 특징과 핵심 차이점을 정리합니다.
