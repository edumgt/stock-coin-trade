01 · INTRODUCTION

SAM은 무엇인가요?

공식 GitHub
AWS SAM

CloudFormation을 확장한 오픈소스 서버리스 애플리케이션 모델입니다. AWS::Serverless::Function 같은 간결한 선언을 실제 AWS 리소스로 변환합니다.

SAM CLI

sam 명령을 제공하는 별도 도구입니다. 초기화, 검증, 빌드, 로컬 실행, 배포와 로그 확인을 한 흐름으로 묶습니다.

Docker

sam build --use-container와 sam local 명령이 Lambda와 비슷한 실행 이미지를 사용할 때 필요합니다. AWS 배포 자체에 항상 필요한 것은 아닙니다.

작성template.yaml→변환SAM Transform→배포CloudFormation Stack→생성Lambda · IAM 등

구분: aws/serverless-application-model은 SAM 규격과 변환 구현 저장소이고, aws/aws-sam-cli는 터미널에서 사용하는 CLI 저장소입니다.

02 · INSTALL

Linux에 SAM CLI 설치

PRECHECK

설치 여부 · Python 버전 · AWS CLI 인증 확인

이미 설치돼 있으면 다시 설치하지 않습니다. 컨테이너 없는 sam build는 템플릿 Runtime과 같은 버전의 로컬 Python이 필요하므로 WSL의 Python 버전을 먼저 확인해 둡니다. 로컬 실행에는 Docker 데몬이, AWS 배포에는 CLI 자격증명과 리전이 필요합니다. 개인 키는 템플릿이나 저장소에 기록하지 않습니다.

환경 · Python · 인증 확인

command -v sam || true
sam --version
aws --version
docker --version
docker info

# 2) WSL Python 설치·버전 확인 (sam build 가 이 버전을 사용)
cat /etc/os-release | grep PRETTY_NAME       # 예: Ubuntu 24.04 LTS
command -v python3 || echo "python3 없음"

STEP 3

검증과 빌드

모든 sam 명령은 template.yaml이 있는 프로젝트 폴더(sam-app-01) 안에서 실행합니다. 템플릿의 함수 이름과 코드 위치를 확인한 뒤 검증하고 Lambda 실행 구조로 빌드합니다. 빌드가 Binary validation failed for python으로 실패하면 템플릿 Runtime과 로컬 Python 버전이 다른 것이므로 아래 블록의 해결 A~C 중 하나를 따릅니다.

템플릿 확인

⚠ 발생할 수 있는 오류
ℹ 기능 설명 — sam build 와 sam build --use-container 의 차이
항목sam buildsam build --use-container
의존성 설치 위치내 WSL 의 로컬 Python(/usr/bin/python3)과 pip 로 설치. 그래서 템플릿 Runtime 과 로컬 버전이 같아야 합니다.Lambda 와 같은 OS·Python 이 들어 있는 빌드 컨테이너 안에서 pip 로 설치. 로컬 Python 버전과 무관합니다.
이미지를 받는 곳이미지 없음 (Docker 불필요)AWS 공개 ECR public.ecr.aws/sam/build-python3.12:latest-x86_64 에서 pull. 템플릿의 Runtime·Architectures 로 태그가 정해집니다.
이미지가 저장되는 곳—내 PC 의 Docker 이미지 저장소(WSL 의 Docker 데이터 디렉터리). docker images | grep sam/build 로 확인. 첫 pull 만 오래 걸리고(수백 MB) 이후 재사용됩니다.
소스가 컨테이너에 들어가는 방식—hello_world/ 를 컨테이너의 /tmp/samcli/source 에 읽기 전용 으로 마운트. 컨테이너는 빌드가 끝나면 삭제되고 이미지만 남습니다(SAM_CONTAINER_ID 는 그 임시 컨테이너 ID).
산출물이 생기는 곳둘 다 같습니다. .aws-sam/build/HelloWorldFunction/ (코드 + 설치된 패키지), .aws-sam/build/template.yaml (CodeUri 가 빌드 폴더로 바뀐 템플릿), .aws-sam/deps/<hash>/ (requirements 해시별 의존성 캐시 — 로그의 "Manifest file is changed (new hash …)" 가 이 캐시 갱신). 이후 sam local invoke·sam deploy 는 이 폴더를 씁니다.
언제 쓰나순수 Python 패키지만 있고 로컬 Python 버전이 Runtime 과 같을 때. 가장 빠릅니다.로컬 Python 버전이 다를 때, 또는 psycopg·numpy 처럼 네이티브 바이너리가 있는 패키지를 Lambda(Amazon Linux) 에 맞게 빌드해야 할 때. Docker 데몬이 켜져 있어야 합니다.

로그 읽기: Running PythonPipBuilder:ResolveDependencies = pip 설치, CopySource = 코드 복사, Starting Build inside a container = 컨테이너 모드, Cache is invalid = 이전 캐시를 버리고 다시 설치.

Runtime 과 로컬 Python 버전 불일치 (가장 흔함)Build Failed Error: PythonPipBuilder:Validation - Binary validation failed for python, searched for python in following locations : ['/usr/bin/python3', '/bin/python3'] which did not satisfy constraints for runtime: python3.14. Do you have python for runtime: python3.14 on your PATH?

원인컨테이너 없는 sam build 는 템플릿 Runtime(python3.14)과 같은 버전의 로컬 Python 으로 pip 의존성을 설치합니다. sam init 이 고른 3.14 와 달리 Ubuntu 에는 3.12 만 있어 검증에서 멈춥니다. python3 --version 과 grep Runtime template.yaml 로 확인합니다.

STEP 6

같은 Lambda에 인터넷 공개 ALB 연결

ALB는 최소 두 가용 영역의 퍼블릭 서브넷이 필요하고 실행 시간 동안 비용이 발생합니다. 아래 예제는 기존 VPC와 퍼블릭 서브넷 두 개를 입력받아 ALB·보안 그룹·리스너·Lambda 대상 그룹·호출 권한을 생성합니다. 기존 template.yaml을 백업한 뒤 전체 내용을 교체합니다.

사용할 VPC와 서로 다른 AZ의 서브넷 확인
# 기본 VPC 확인. 결과가 None이면 사용할 VPC ID를 직접 정합니다.
aws ec2 describe-vpcs \
  --filters Name=is-default,Values=true \
  --query 'Vpcs[0].VpcId' --output text

# 위 VPC의 서브넷과 가용 영역 확인
VPC_ID=vpc-0123456789abcdef0
aws ec2 describe-subnets \
  --filters Name=vpc-id,Values="$VPC_ID" \
  --query 'Subnets[].{SubnetId:SubnetId,AZ:AvailabilityZone,PublicIp:MapPublicIpOnLaunch}' \
  --output table

# 서로 다른 AZ의 퍼블릭 서브넷 두 개를 기록합니다.
# 예: subnet-aaa... (ap-northeast-2a), subnet-bbb... (ap-northeast-2b)
template.yaml — API Gateway + Lambda + ALB 전체 예제
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: One Lambda exposed by API Gateway and an internet-facing ALB

Parameters:
  VpcId:
    Type: AWS::EC2::VPC::Id
  PublicSubnetA:
    Type: AWS::EC2::Subnet::Id
  PublicSubnetB:
    Type: AWS::EC2::Subnet::Id

Resources:
  HelloWorldFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: hello_world/
      Handler: app.lambda_handler
      Runtime: python3.12
      Architectures:
        - x86_64
      Timeout: 10
      Events:
        HelloWorldApiEvent:
          Type: Api
          Properties:
            Path: /hello
            Method: get

  AlbSecurityGroup:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: Allow public HTTP for the SAM ALB example
      VpcId: !Ref VpcId
      SecurityGroupIngress:
        - IpProtocol: tcp
          FromPort: 80
          ToPort: 80
          CidrIp: 0.0.0.0/0

  ApplicationLoadBalancer:
    Type: AWS::ElasticLoadBalancingV2::LoadBalancer
    Properties:
      Scheme: internet-facing
      Type: application
      SecurityGroups:
        - !Ref AlbSecurityGroup
      Subnets:
        - !Ref PublicSubnetA
        - !Ref PublicSubnetB

  AlbInvokePermission:
    Type: AWS::Lambda::Permission
    Properties:
      Action: lambda:InvokeFunction
      FunctionName: !Ref HelloWorldFunction
      Principal: elasticloadbalancing.amazonaws.com
      SourceAccount: !Ref AWS::AccountId

  LambdaTargetGroup:
    Type: AWS::ElasticLoadBalancingV2::TargetGroup
    DependsOn: AlbInvokePermission
    Properties:
      TargetType: lambda
      Targets:
        - Id: !GetAtt HelloWorldFunction.Arn

  HttpListener:
    Type: AWS::ElasticLoadBalancingV2::Listener
    Properties:
      LoadBalancerArn: !Ref ApplicationLoadBalancer
      Port: 80
      Protocol: HTTP
      DefaultActions:
        - Type: forward
          TargetGroupArn: !Ref LambdaTargetGroup

Outputs:
  HelloWorldApi:
    Description: API Gateway endpoint
    Value: !Sub 'https://${ServerlessRestApi}.execute-api.${AWS::Region}.${AWS::URLSuffix}/Prod/hello/'
  AlbUrl:
    Description: ALB endpoint
    Value: !Sub 'http://${ApplicationLoadBalancer.DNSName}/'

권한 범위: 예제의 SourceAccount는 같은 AWS 계정의 ELB 서비스만 Lambda를 호출하도록 제한하면서 Target Group과 Permission 사이의 순환 참조를 피합니다. 운영 환경에서는 HTTPS 리스너, ACM 인증서, 더 제한적인 인바운드 CIDR, WAF와 애플리케이션 인증을 함께 설계해야 합니다.
