Binance Spot API: 공개 시세부터 Testnet까지

이 웹앱은 API Key 없이 쓸 수 있는 공개 시세·호가 API를 먼저 사용합니다. 계정·주문 API는 서명과 별도 권한이 필요하며 운영 키를 브라우저에 두지 않습니다.

1 · 공개 API

Key 없이 현재가·호가를 확인합니다

24시간 시세

GET /api/v3/ticker/24hr?symbol=BTCUSDT

호가

GET /api/v3/depth?symbol=BTCUSDT&limit=10

캔들

GET /api/v3/klines의 interval·limit을 공식 문서와 대조합니다.

curl 'https://api.binance.com/api/v3/ticker/24hr?symbol=BTCUSDT'
curl 'https://api.binance.com/api/v3/depth?symbol=BTCUSDT&limit=10'

2 · 인증 API와 모의주문

운영 주문은 만들지 않고 Spot Testnet을 먼저 사용합니다

서명 API는 API Key와 Secret, timestamp, HMAC SHA-256 서명이 필요합니다. 권한은 조회와 거래를 분리하고, 출금 권한은 API 키에 부여하지 않는 것을 원칙으로 합니다. Spot Testnet 키와 운영 키는 분리합니다.

BINANCE_API_KEY=TESTNET_KEY
BINANCE_API_SECRET=TESTNET_SECRET
BINANCE_BASE_URL=https://testnet.binance.vision
주의: 이 웹앱에는 Binance 주문·잔고·출금 호출이 없습니다. Testnet에서도 주문 요청은 상태를 바꾸므로 별도의 확인·중복 방지·취소 확인·감사 기록이 필요합니다.

연계 실습 — AI Sheet·Quant·에러분석 (60분)

마지막 날에는 시세 응답을 단순 표시하는 데서 끝내지 않고, 분석 결과의 재현성과 운영 오류 대응을 함께 연습한다. 공개 API라 해도 호출 실패와 데이터 지연은 발생할 수 있다.

기능구현·사용 순서역할확인 항목
AI Sheet/ai-sheet.html조사·요약 담당근거 링크와 요약을 분리해 기록하고, API Key·계좌번호를 입력하지 않는다.
PostgreSQL Quant/quant.html?tab=simulation전략 검증 담당OHLCV·전략·체결·성과 지표가 분리된 구조와 백테스트 가정을 확인한다.
에러분석/error-analysis.html운영·장애 대응 담당서버 4xx/5xx와 브라우저 오류의 발생 시각·경로·원인 설명·마스킹된 스택을 읽는다.
오류 재현 기록공개 API 테스트에서 잘못된 심볼을 한 번만 입력품질 담당HTTP 상태, 재현 절차, 기대/실제 결과를 기록하고 무한 재시도는 하지 않는다.

구현 관점: system_error_log는 서버와 브라우저 오류를 통합하되 토큰·비밀번호·API Key를 마스킹한다. 전체 로그 열람은 관리자 전용이며, 오류 상세에는 해결에 필요한 경로·상태·스택만 남긴다. 분석 결과도 외부 API의 일시 오류와 데이터 공급 지연을 고려해 재실행 가능하게 설계한다.

통합 운영 점검 확장: AWS Secrets Manager 트랙

키 파일 대신 AWS Secrets Manager의 JSON 보안 암호에서 키를 읽는 별도 트랙이다. 기존 키 파일 트랙과 URL·모듈이 분리되어 있어 한쪽을 설정하지 않아도 다른 쪽에 영향이 없다. EC2 운영 환경으로 확장할 때 5개 모듈의 키 관리를 한 곳으로 모으는 사례로 소개한다.

항목내용
코드aws_secret_store.py, broker_test_aws.py, alpaca_test_aws.py
API/api/aws-broker-test/secrets/status, /kis/quote, /kis/balance, /kb/token, /kb/quote, /api/aws-alpaca-test/paper/account, /positions, /clock, /asset (모두 읽기 전용, 주문 없음)
화면/aws-broker-api-test.html, /aws-alpaca-test.html, /learning/aws-ssm-key-management.html
환경변수AWS_REGION, AWS_SECRETS_MANAGER_PREFIX(기본 stock-coin-trade), 로컬 개발 시에만 AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY/AWS_SESSION_TOKEN
보안 암호 이름stock-coin-trade/kis, stock-coin-trade/kb, stock-coin-trade/alpaca (각 JSON)
사전 준비IAM에 secretsmanager:DescribeSecret + secretsmanager:GetSecretValue 최소 권한. EC2는 인스턴스 프로파일 권장
