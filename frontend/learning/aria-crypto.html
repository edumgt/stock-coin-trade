ARIA 알고리즘으로 문자열 암복호화하기

ARIA는 국가보안기술연구소(NSRI)와 학계가 함께 설계해 2004년 한국 산업표준 KS X 1213으로 제정된 국산 블록 암호입니다. AES와 같은 128비트 블록·128/192/256비트 키 구조이며, 국제 표준(RFC 5794, ISO/IEC 18033-3)에도 등재되어 있어 공공기관 시스템의 개인정보 암호화에 널리 쓰입니다. 이 페이지는 순수 파이썬 구현 + Flask API + 웹앱 폼으로 실제 문자열이 암호문으로 바뀌고 다시 돌아오는 과정을 보여줍니다.

1키 준비비밀번호에서 키 유도 또는 Secrets Manager에서 로드
2암호화ARIA-CBC + PKCS#7, 랜덤 IV 16바이트
3저장·전송base64(IV‖암호문) 문자열 한 개로 DB·JSON에 저장
4복호화같은 키로 IV 분리 후 원문 복원

1. ARIA는 어떤 알고리즘인가

ARIA는 SPN(Substitution-Permutation Network) 구조입니다. 매 라운드마다 ① 라운드 키 XOR → ② 4종의 S-box 치환(SB1·SB2·SB3·SB4) → ③ 16×16 이진 행렬 확산(A)을 반복하고, 마지막 라운드만 확산 대신 라운드 키를 한 번 더 XOR합니다. S-box 2종은 AES처럼 GF(28) 역원·x247의 아핀 변환으로 정의되고, 확산 행렬 A는 자기 자신이 역행렬인 involution이라 복호화가 같은 코드로 동작합니다.

2. 파이썬 코드 — 순수 파이썬 ARIA 모듈 사용

백엔드의 python-stock-backend/aria_cipher.py는 외부 패키지 없이 ARIA 블록 암호와 CBC/PKCS#7, 문자열 헬퍼를 제공합니다. 테스트(test_aria_cipher.py)에서 RFC 5794 벡터 3종과 OpenSSL aria-*-cbc 출력과 일치함을 검증합니다.

① 블록 단위 암복호화 — 표준 벡터 확인

from aria_cipher import ARIA key = bytes.fromhex("000102030405060708090a0b0c0d0e0f") # 16바이트 = ARIA-128 pt = bytes.fromhex("00112233445566778899aabbccddeeff") aria = ARIA(key) ct = aria.encrypt_block(pt) print(ct.hex()) # d718fbd6ab644c739da95f3be6451778 print(aria.decrypt_block(ct) == pt) # True

② 문자열 암복호화 — CBC + PKCS#7 + base64

from aria_cipher import derive_key, encrypt_text, decrypt_text # 데모: 비밀번호를 SHA-256으로 32바이트(=256비트) 키로 유도 key = derive_key("my-secret-passphrase", key_bits=256) token = encrypt_text("홍길동 010-1234-5678", key) print(token) # 'Qm9…' base64(IV 16B ‖ 암호문). IV가 랜덤이라 매번 다름 plain = decrypt_text(token, key) print(plain) # 홍길동 010-1234-5678 # 잘못된 키로 복호화하면 패딩 검증에서 ValueError 발생 decrypt_text(token, derive_key("wrong")) # ValueError: 잘못된 패딩입니다…

③ 운영 환경 — 키를 AWS Secrets Manager에서 읽기

비밀번호 유도는 학습용입니다. 운영에서는 32바이트 난수 키를 Secrets Manager의 JSON 보안 암호에 두고, 이 저장소의 aws_secret_store.get_secret()로 읽어 ARIA()에 직접 넘깁니다. 다음 단계(2. 키 적재·연결 가이드)와 같은 IAM Role 구성을 그대로 재사용합니다.

import base64, os from aws_secret_store import get_secret # boto3 SecretsManager.get_secret_value 래퍼 from aria_cipher import encrypt_text, decrypt_text # Secrets Manager: stock-coin-trade/aria = {"key_b64": "<base64 32바이트>"} # 최초 1회 생성: python -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())" secret = get_secret("aria") key = base64.b64decode(secret["key_b64"]) # 32바이트 → ARIA-256 phone_enc = encrypt_text("010-1234-5678", key) # DB의 phone_enc 컬럼에 저장 phone = decrypt_text(phone_enc, key) # 화면 표시 직전에만 복호화

④ OpenSSL로 교차 검증 (같은 키·IV면 바이트 단위로 동일)

# 파이썬 결과와 OpenSSL 결과가 같은지 확인 printf 'hello aria' | openssl enc -aria-256-cbc -K <64자리 hex 키> -iv <32자리 hex IV> | xxd -p # 파이썬 쪽 ARIA(key).encrypt_cbc(b"hello aria", iv).hex()

3. Flask API 명세 — /api/aria

블루프린트 python-stock-backend/aria_api.py가 제공합니다. 키는 요청의 passphrase에서 유도하거나, 생략 시 서버 환경변수 ARIA_DEMO_KEY(미설정이면 데모 고정 키)를 사용합니다. 세션·로그인은 필요 없습니다.

엔드포인트요청 본문 (JSON)응답
POST /api/aria/encrypttext(필수, ≤10,000자), passphrase(선택), key_bits(128·192·256, 기본 256)ok, algorithm, padding, encoding, key_bits, key_source, cipher, cipher_length
POST /api/aria/decryptcipher(필수, base64), passphrase, key_bitsok, algorithm, key_bits, key_source, text
GET /api/aria/info—표준·라운드 정보와 RFC 5794 자체 검증 결과(self_test.passed)

실패 시 HTTP 400과 {"ok": false, "message": "…"}를 돌려줍니다. 키가 다르면 PKCS#7 패딩 검증에 실패해 잘못된 패딩 메시지가 납니다.

curl 예시

# 암호화 curl -s -X POST http://localhost:3333/api/aria/encrypt \ -H 'Content-Type: application/json' \ -d '{"text":"홍길동 010-1234-5678","passphrase":"demo-pass","key_bits":256}' # → {"ok":true,"algorithm":"ARIA-256-CBC","cipher":"…base64…", ...} # 복호화 curl -s -X POST http://localhost:3333/api/aria/decrypt \ -H 'Content-Type: application/json' \ -d '{"cipher":"…base64…","passphrase":"demo-pass","key_bits":256}' # → {"ok":true,"text":"홍길동 010-1234-5678", ...}

웹앱(JavaScript) 호출 예시 — 저장 전에 암호화, 표시 직전에 복호화

async function encryptField(text, passphrase) { const res = await fetch('/api/aria/encrypt', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ text, passphrase, key_bits: 256 }), }); const data = await res.json(); if (!data.ok) throw new Error(data.message); return data.cipher; // 이 문자열을 폼의 hidden 필드/DB 컬럼에 저장 } async function decryptField(cipher, passphrase) { const res = await fetch('/api/aria/decrypt', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ cipher, passphrase, key_bits: 256 }), }); const data = await res.json(); return data.ok ? data.text : '(복호화 실패)'; } // 사용: 회원 전화번호 입력 → 암호문으로 바꿔 저장 → 조회 화면에서 복호화 표시 const phoneEnc = await encryptField(form.phone.value, passphrase); document.querySelector('#phone-display').textContent = await decryptField(phoneEnc, passphrase);

4. 라이브 데모 — 웹앱에서 문자열이 바뀌는 과정

아래 폼은 위 API를 그대로 호출합니다. 왼쪽에서 평문을 암호화하면 base64 암호문이 오른쪽 복호화 칸에 자동으로 채워지고, 복호화 버튼으로 원문이 돌아오는지 확인할 수 있습니다.

사용 방법 (순서대로)

STEP 1비밀번호·키 길이 정하기상단 비밀번호 칸의 값이 SHA-256을 거쳐 ARIA 키가 됩니다. 비우면 서버 환경변수 ARIA_DEMO_KEY의 기본 키를 씁니다. 키 길이는 128/192/256비트 중 선택하며, 암호화와 복호화에서 같은 비밀번호·같은 키 길이를 써야 합니다.
STEP 2평문 입력 후 암호화왼쪽 평문 칸에 보호할 문자열(전화번호, 계좌번호, 메모 등 최대 10,000자)을 적고 암호화를 누릅니다. 서버가 랜덤 IV 16바이트를 만들어 ARIA-CBC로 암호화하고, base64(IV‖암호문) 한 줄을 돌려줍니다.
STEP 3암호문 확인결과가 왼쪽 암호문 칸에 표시되고 오른쪽 복호화 입력칸에도 자동으로 복사됩니다. 복사 버튼으로 클립보드에 담아 DB 컬럼이나 다른 시스템에 붙여넣는 상황을 가정해 보세요. 아래 문자열 변경 흐름 표가 방금 입력한 값으로 채워집니다.
STEP 4복호화로 원문 복원오른쪽 복호화를 누르면 같은 비밀번호·키 길이로 IV를 분리해 원문을 복원하고 복원된 평문 칸에 표시합니다. STEP 2에서 입력한 문자열과 글자 하나까지 같은지 확인하세요.
STEP 5실패 사례 실험비밀번호를 한 글자만 바꾸거나 키 길이를 다르게 고른 뒤 복호화를 누르면 잘못된 패딩 오류(HTTP 400)가 납니다. 암호문 중간 글자를 하나 고쳐도 마찬가지입니다. 키·암호문 무결성이 깨지면 복호화가 거부되는 것을 확인하는 단계입니다.
STEP 6같은 평문 다시 암호화같은 평문으로 암호화를 한 번 더 누르면 암호문이 전혀 다른 값으로 바뀝니다. IV가 매번 랜덤이기 때문이며, 그래도 복호화하면 같은 원문이 나옵니다. 따라서 암호문끼리 같은지 비교하는 검색은 불가능하고, 필요하면 별도 해시 컬럼을 둡니다.

결과 읽는 법

  • 암호문 길이가 64자인 이유 · IV 16바이트 + 암호문. 평문이 16바이트 이하면 패딩 후 1블록(16바이트)이라 총 32바이트, base64로 44자. 17~32바이트면 2블록이라 48바이트 → 64자. 예시 평문 "홍길동 010-1234-5678"은 UTF-8로 23바이트라 64자가 됩니다.
  • 키 출처(key_source) · passphrase는 입력한 비밀번호로 유도한 키, server는 비밀번호를 비워 서버 기본 키를 쓴 경우입니다.
  • 오류 메시지 · "잘못된 패딩" = 키 불일치 또는 암호문 손상, "base64 문자열이어야" = 암호문 형식 오류, "너무 짧습니다" = IV+1블록(32바이트) 미만.
