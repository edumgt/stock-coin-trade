호출 경로 · 이 저장소 백엔드 vs KIS 직접

브라우저는 KIS 를 직접 호출하지 않고, 항상 이 저장소의 백엔드를 거칩니다

KIS 모의투자 실습의 모든 화면은 브라우저 → nginx(/api/* 프록시) → Flask 백엔드(python-stock-backend) → KIS Testbed 순서로 동작합니다. App Key·Secret·계좌번호·접근 토큰은 백엔드에만 있고, 브라우저에는 백엔드가 정리한 JSON 만 돌아옵니다. 브라우저가 openapivts.koreainvestment.com 에 직접 접속하는 코드는 없습니다(키 노출과 CORS 문제 때문입니다). KIS 를 직접 호출하는 것은 아래 표의 마지막 두 줄(CLI 스크립트, MCP)뿐입니다.

유의사항 · 시간 제약

KIS Testbed 는 시간 제한이 많습니다. 실습 전에 알아 두세요

이 웹앱을 만들고 검증하면서 실제로 걸렸던 제한을 정리했습니다. 대부분 "잠시 기다렸다가 한 번만 다시" 하면 풀리며, 새로고침·버튼 연타는 오히려 제한 시간을 늘립니다.

제약증상 (오류 코드)이 웹앱의 처리실습자가 할 일
접근 토큰 발급 1분당 1회HTTP 403, EGW00133 또는 "접근토큰 발급 잠시 후 다시 시도하세요(1분당 1회)"토큰을 약 24시간 서버 메모리에 캐시해 재사용합니다. 단, 백엔드 컨테이너를 재시작하면 캐시가 사라져 새로 발급합니다.백엔드를 1분 안에 두 번 재시작하지 않습니다. 재시작 직후 첫 조회가 실패하면 1분 뒤 한 번만 다시 시도합니다.
초당 거래건수 제한EGW00201 "초당 거래건수를 초과하였습니다" (HTTP 500)시세 호출은 0.5~1초, 계좌 TR 은 1.1초, 주문 호출은 0.6초 간격을 두고 제한 응답이면 1~2회 자동 재시도합니다. 현재가는 3초, 차트는 30초 캐시합니다.버튼을 연속으로 누르지 않습니다. 여러 사람이 같은 키·같은 공인 IP 로 동시에 실습하면 한 사람의 연타가 전체를 막을 수 있습니다.
모의투자 영업일·장 운영시간40100000 "모의투자 영업일이 아닙니다", 장 마감 후 주문 거부주문 흐름 테스트는 거절 메시지를 그대로 표시하고 주문을 남기지 않습니다.주문 흐름 테스트는 영업일 09:00–15:30 에만 실행합니다. 조회(현재가·차트·잔고)는 휴장일에도 마지막 값이 조회됩니다.
1분봉은 당일만 제공휴장일·장 시작 전에는 분봉이 비어 있음KIS 종목 차트는 "당일 분봉 데이터가 없습니다" 안내 후 일봉으로 확인하도록 합니다.분봉 실습은 장중에 합니다. 휴장일에는 일·주·월봉으로 진행합니다.
호출당 건수 제한 → 여러 번 호출기간별시세 100건, 당일분봉 30건, 잔고 20건, 일별주문체결 15건(모의 기준)차트 300개는 최대 4회, 분봉 240개는 최대 8회 호출을 1초 간격으로 이어 붙이므로 4~10초가 걸립니다. 탐색기는 최초 페이지만 조회합니다.차트 로딩 표시가 사라질 때까지 기다립니다. 캔들 수를 늘릴수록 오래 걸립니다.
주문 흐름 동시 실행 금지"모의 주문 흐름 테스트가 이미 실행 중입니다"서버 락으로 두 번째 실행을 즉시 거부합니다. 한 번의 흐름은 주문·정정·취소 3회 호출과 간격을 합쳐 2~5초, 보정 조회가 붙으면 최대 1분 안팎입니다.완료 메시지를 본 뒤 다시 실행합니다. 화면 안내는 "최대 1분"으로 표시됩니다.
정정 타임아웃 시 미체결 보정정정·취소 응답 없음(네트워크 시간 초과 15초)오늘 미체결을 조회해 남은 주문을 모두 취소하고, 실패하면 "모의투자 화면에서 직접 확인" 안내를 냅니다.결과의 정정·취소 줄을 끝까지 읽고, 실패 안내가 있으면 한국투자증권 모의투자 화면에서 미체결을 확인합니다.
프록시·요청 시간 초과"서버 응답을 해석할 수 없습니다 (HTTP 502/504)"KIS 호출 1건당 15초 제한, nginx 는 200초까지 기다립니다. 백엔드가 내려가 있으면 상태 코드만 안내합니다.백엔드 컨테이너 상태(docker compose ps)를 확인한 뒤 다시 시도합니다.
실습 진행 팁: 한 화면에서 한 번에 하나씩 호출하고, 실패하면 오류 코드를 기록한 뒤 위 표의 "할 일"대로 기다렸다가 재시도하세요. 진행자는 실습 전에 백엔드를 한 번만 기동해 토큰이 미리 발급되도록 하고, 주문 흐름 실습은 장중 시간대로 잡습니다.

def get_access_token():
    response = requests.post(

        headers={"content-type": "application/json; charset=utf-8"},

오전 핵심 개념

  1. account의 하이픈 앞은 CANO, 뒤는 계좌상품코드다. 임의로 -01, -02를 바꾸지 않는다.
  2. 시세·호가·차트에는 키가 필요하고, 잔고·주문성 기능에는 계좌 설정도 필요하다.

  4. 공식 구현·샘플의 기준은 https://github.com/koreainvestment/open-trading-api다.

CANO와 계좌상품코드

CANO는 한국투자증권(KIS) OpenAPI에서 쓰는 필드명으로, 종합계좌번호(Comprehensive Account NO.)의 약자다. KIS 계좌번호는 12345678-01 형태이고, API 요청 시 두 부분으로 나눠 보낸다.

위치필드명의미자릿수
하이픈 앞CANO종합계좌번호 (고객 계좌 식별)8자리
하이픈 뒤ACNT_PRDT_CD계좌상품코드 (계좌 종류)2자리

계좌상품코드는 계좌 개설 시 증권사가 부여한 값이라 사용자가 고를 수 없다. 예를 들어 01은 종합/위탁 계좌, 03은 선물옵션 계좌, 22는 연금 계좌처럼 종류마다 정해져 있다. "01이 안 되니 02로 바꿔 보자" 식으로 임의 수정하면 KIS 서버가 계좌를 찾지 못해 조회와 주문이 모두 실패한다.

오후 토의: 역할과 안전장치

  • 프론트엔드 역할: 종목코드 검증, 사용자 확인, 결과 표시. Key·Secret을 절대 받지 않는다.
  • 백엔드 역할: Testbed 토큰 발급·캐시, KIS 호출, 안전한 오류 변환, 주문 흐름 잠금.
  • 운영자 역할: 모의 키의 만료·해지 상태, Docker Secret mount, 접근 로그를 관리한다.
  • 학습자 역할: 자동 반복 호출을 하지 않고, 주문성 테스트는 확인 문구를 읽고 한 번씩 실행한다.

환경변수 사용 시 주의

  • .env의 값은 docker-compose.yml의 python-backend.environment 블록을 거쳐 컨테이너로 전달된다. 이 블록에 없는 변수는 .env에 적어도 무시된다.
  • KIS_ACCOUNT_NO는 12345678-01처럼 CANO와 상품코드를 하이픈으로 이어 한 값으로 적는다. 상품코드를 별도 변수로 넣는 방식은 지원하지 않는다.
  • 백엔드는 항상 Testbed 도메인만 사용하므로 모의/실전 전환 변수는 없다. Alpaca도 Paper 도메인이 코드에 고정되어 있다.
  • Docker 없이 python app.py로 직접 실행하면 app.py가 저장소 루트의 .env를 읽는다(이미 설정된 환경변수 우선).
