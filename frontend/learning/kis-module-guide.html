KIS Developers

API 문서·Testbed·오류코드·샘플을 확인하고 Open API 서비스를 신청하는 공식 개발자센터입니다.

LESSON 1 · 한국투자증권 가입과 계좌 준비

먼저 증권사 고객 ID와 목적에 맞는 계좌를 준비합니다

1

한국투자증권 계정 만들기 또는 로그인

KIS Developers의 API 신청 버튼은 한국투자증권 로그인 화면으로 이동합니다. 이미 계좌가 있다면 고객 ID 상태와 연결된 계좌를 확인합니다. 이 웹앱의 회원가입 정보나 비밀번호를 입력하는 곳이 아닙니다.

2

계좌가 없다면 비대면 계좌개설 진행

한국투자증권 안내상 모바일 계좌개설에는 본인 신분증, 본인 명의 휴대폰, 보유 은행·증권사 계좌가 필요합니다. 계좌 개설 뒤 온라인 이용을 위해 고객 ID 등록·계좌 연결이 필요한 경우도 있습니다.

3

모의와 실전을 여기서 갈라서 결정

이 웹앱 모듈은 모의 Testbed 조회 전용이므로 처음에는 모의투자 신청과 모의 API 키만 사용합니다. 실전 계좌·실전 키는 이 모듈 설정에 넣지 않습니다.

한국투자증권 로그인·가입 ↗ KIS Developers 열기 ↗
입력 위치를 구분하세요: 주민등록증, 휴대폰 인증, 계좌 비밀번호, 인증서 정보는 한국투자증권 공식 앱·웹사이트에서만 입력합니다. 이 웹앱과 KIS Developers 문서 페이지에는 입력하지 않습니다.
LESSON 1-1 · 모의투자 계좌 받기

KIS Testbed용 모의계좌를 신청하고 번호를 확인합니다

이 웹앱에서 사용하는 KIS 계좌는 실전 계좌가 아니라 한국투자증권의 주식/선물옵션 모의투자에서 발급받는 모의투자 전용 계좌입니다. 모의투자는 투자 체험과 학습을 위한 서비스이며, 신청 가능한 리그·기간·대상 상품은 그때그때 공식 화면의 안내를 따릅니다.

1

공식 모의투자 안내로 이동하고 로그인

아래의 공식 안내에서 모의투자안내 또는 참가 신청 화면으로 이동합니다. 한국투자증권 고객 ID로 로그인하며, 이 웹앱 계정으로는 신청할 수 없습니다.

2

참가 신청 정보를 선택

신청 화면에서 모의투자 비밀번호, 참여 리그 또는 투자 기간, 개인정보·약관 동의 등 현재 표시되는 항목을 확인하고 제출합니다. 항목명과 참가 조건은 바뀔 수 있으므로 화면의 최신 안내를 우선합니다.

3

신청 완료 후 모의계좌 정보 확인

모의투자 서비스의 나의계좌 → 계좌정보에서 새로 생성된 모의투자 계좌번호를 확인합니다. 계좌번호 전체를 메신저·캡처·Git에 공유하지 않습니다.

4

계좌번호를 kis.key 형식으로 분리

화면의 계좌번호가 12345678-01처럼 보이면 앞 8자리(CANO)와 뒤 2자리(상품코드)를 하이픈으로 유지해 account=12345678-01로 적습니다. 이 값은 잔고 조회와 향후 주문성 API에 필요합니다.

5

모의계좌와 모의 API 키를 같은 환경으로 맞춤

다음 레슨에서 KIS Developers API 신청 시 모의투자 계좌에 대응하는 키를 발급받습니다. 실전 계좌·실전 키와 한 파일에 섞지 않습니다.

확인 항목이 웹앱에 쓰는 방법주의
모의투자 계좌번호account=CANO-상품코드로 kis.key에 저장현재가·차트·호가·지수 조회에는 필요 없고, 잔고 조회부터 필요합니다.
모의투자 비밀번호한국투자증권 모의투자 서비스에서만 사용kis.key, 이 웹앱, KIS API 요청에 넣지 않습니다.
실전 증권계좌이 모듈에서는 사용하지 않음실전 계좌번호·실전 키를 Testbed 파일에 기록하지 않습니다.

LESSON 4 · 이 웹앱의 환경 설정

키는 서버의 kis.key로 전달합니다

1

모의 키 두 값을 정확히 기록

App-KEY와 Secret은 KIS가 발급한 그대로 사용합니다. 공백·따옴표·키 이름 오타가 있으면 인증에 실패합니다.

2

프로젝트 루트에 kis.key 생성

Docker 실행 시 이 파일은 컨테이너의 /run/secrets/kis.key로 읽기 전용 전달됩니다. *.key와 .env는 Git 제외 대상입니다.

3

잔고 조회를 할 경우에만 모의계좌 추가

계좌번호는 12345678-01처럼 CANO와 상품코드를 하이픈으로 연결합니다. 현재가·차트·호가·지수 조회에는 필요하지 않습니다.

# 프로젝트 루트의 kis.key (절대 커밋하지 않음)
app_key=모의투자_App_Key
secret=모의투자_App_Secret
account=12345678-01
로컬 실행과 Docker 실행의 차이: 로컬에서 Python 스크립트를 직접 실행할 때는 KIS_APP_KEY, KIS_APP_SECRET 환경변수를 사용할 수 있습니다. 그러나 현재 Docker Compose 구성의 웹앱 백엔드는 KIS 환경변수를 전달하지 않고 kis.key 파일을 읽습니다. Docker 웹앱 테스트는 위 파일 방식을 사용하세요.
주의: 키·Secret·접근 토큰·계좌번호는 이 페이지나 테스트 화면의 입력창에 넣지 않습니다. 서버 파일 또는 배포 Secret에만 둡니다. 외부에 공개된 환경이라면 잔고 조회 경로에 별도의 접근 통제도 필요합니다.
LESSON 4-1 · kis.key 상세

파일 형식·읽는 위치·사용 범위를 정확히 맞춥니다

이 웹앱은 /home/ubuntu/stock-coin-trade/kis.key를 직접 읽거나, Docker 컨테이너 안의 /run/secrets/kis.key를 읽습니다. 현재 파일에 인증 키만 있다면 시세·차트·호가·지수는 가능하지만, 잔고 조회와 주문성 API에는 account도 필요합니다.

항목필수 여부형식 및 용도
app_key필수KIS Developers에서 발급한 모의투자 App Key입니다. App-KEY 표기도 읽을 수 있으나, 이 파일에서는 소문자 app_key를 권장합니다.
secret필수위 App Key에 대응하는 모의투자 App Secret입니다. 공백·따옴표·인라인 주석을 붙이지 않습니다.
account잔고 조회 시 필수CANO-상품코드 형식입니다. 예: 12345678-01. 하이픈 앞은 8자리 계좌번호, 뒤는 계좌상품코드입니다.
# 올바른 예시: 한 줄에 한 값만 둡니다.
app_key=발급받은_모의_App_Key
secret=발급받은_모의_App_Secret
account=12345678-01

# 잘못된 예시: 이 파서는 '#' 뒤쪽도 값으로 읽습니다.
account=12345678-01 # 모의 계좌
1

파일 권한과 Git 제외 확인

파일은 프로젝트 루트에 두고 Git에 추가하지 않습니다. 이 프로젝트의 .gitignore는 *.key를 제외합니다. 배포 환경에서는 호스트 파일 대신 플랫폼 Secret을 같은 경로로 mount하는 방식을 사용합니다.

2

우선순위 이해

백엔드는 KIS_APP_KEY와 KIS_APP_SECRET 환경변수가 모두 있으면 그것을 먼저 사용하고, 없을 때 kis.key를 사용합니다. 계좌는 KIS_ACCOUNT_NO가 우선이며 없으면 파일의 account를 읽습니다.

3

Docker 재생성 후 확인

컨테이너는 kis.key를 읽기 전용으로 mount합니다. 파일을 새로 만들거나 변경했다면 docker compose up -d --build --no-deps python-backend로 백엔드를 재생성한 뒤 조회합니다.

실전 키 금지: 이 파일에는 실전 App Key·Secret 또는 실전 계좌번호를 넣지 마세요. 현재 이 웹앱 KIS 모듈은 openapivts Testbed 조회에만 사용합니다.

LESSON 6 · 기능별 실습

조회 결과를 비교하며 읽습니다

현재가

가격·전일 대비·등락률·거래량·체결시각을 확인합니다. 계좌 정보가 필요 없습니다.

일봉과 호가

최근 일봉의 OHLCV와 매수·매도 10단계 호가를 각각 조회합니다. 투자 판단이나 주문 신호로 자동 연결되지는 않습니다.

잔고와 지수

잔고는 설정한 모의계좌만, 지수는 코스피(0001)·코스닥(1001)만 지원합니다.

LESSON 7 · API 실행 예시

현재 구현된 KIS 조회 API를 하나씩 실행합니다

아래 명령은 브라우저가 아닌 터미널에서 이 웹앱 백엔드로 요청하는 예시입니다. KIS App Key·Secret은 명령에 넣지 않으며 서버의 kis.key만 사용합니다. 응답의 ok: true가 성공이고, ok: false면 화면의 메시지로 설정·제한 상태를 확인합니다.

기능필요한 설정확인할 응답
현재가app_key, secretprice, change, changeRate, volume
일봉app_key, secretcandles의 날짜·시가·고가·저가·종가·거래량
10단계 호가app_key, secretlevels의 매도·매수 가격과 잔량
시장지수app_key, secret코스피(0001) 또는 코스닥(1001)의 지수·등락률
잔고·평가액위 두 키 + accountcashBalance, totalEvalAmount, holdings
# 1. 삼성전자 현재가 — 계좌 설정 불필요
curl 'http://localhost:3000/api/broker-test/kis/quote?symbol=005930'

# 2. 최근 일봉
curl 'http://localhost:3000/api/broker-test/kis/chart?symbol=005930'

# 3. 매수·매도 10단계 호가
curl 'http://localhost:3000/api/broker-test/kis/orderbook?symbol=005930'

# 4. 코스피(0001). 코스닥은 code=1001
curl 'http://localhost:3000/api/broker-test/kis/index?code=0001'

# 5. 모의계좌 잔고·평가액 — kis.key의 account 설정 필요
curl 'http://localhost:3000/api/broker-test/kis/balance'

# 6. UI로 같은 기능 실행
# http://localhost:3000/broker-api-test.html
호출 순서: 처음에는 현재가 1회만 성공시킨 뒤 일봉·호가·지수로 넓히고 마지막에 잔고를 확인하세요. Testbed 토큰 발급·호출에는 제한이 있으므로 실패할 때 새로고침을 연속으로 반복하지 않습니다. 백엔드는 토큰과 짧은 시세 결과를 메모리에 캐시합니다.
주문은 이 주소들로 실행하지 않습니다: 아래 조회 API와 달리 주문·정정·취소는 로그인 후 모의 주문 흐름 테스트에서만 실행합니다. 현재 고정된 안전 가격·수량으로 주문 뒤 취소하는 점검이며, 주문성 기능은 언제나 중복 방지·취소 확인·감사 기록을 갖춘 별도 흐름으로 다뤄야 합니다.
LESSON 8 · 공식 GitHub를 읽는 법

샘플 코드는 복사 대상이 아니라 API 검증의 기준점입니다

한국투자증권의 공식 Open Trading API GitHub는 REST·WebSocket 호출 형태와 응답 처리 예시를 제공합니다. 샘플은 수시로 바뀔 수 있으므로, 실제 적용 전에는 KIS Developers의 최신 API 명세와 함께 확인합니다.

공식 저장소 영역모의투자 웹앱에서 배우는 점적용 원칙
examples_llm한 API를 한 파일·한 함수 단위로 호출하고 성공 여부를 확인하는 방식현재가, 잔고, 주문처럼 기능 하나씩 Testbed에서 검증합니다.
examples_user사용자 시나리오에 맞춘 REST·WebSocket 조합과 공통 인증 사용법구조만 참고하고, 브라우저에 App Secret을 전달하는 코드는 가져오지 않습니다.
kis_auth.py 및 설정 예시토큰 발급, 공통 헤더, 실전·모의 환경 분리의 필요성이 웹앱은 kis.key와 서버 측 KIS 클라이언트로 같은 책임을 분리합니다.
stocks_info종목코드·시장 정보 파일을 별도 데이터로 관리하는 방식화면 입력값을 검증하고, 종목 마스터 갱신 주기를 운영 항목으로 둡니다.
전략·백테스트 예시시세 분석과 주문 실행은 다른 책임이라는 점백테스트 결과를 곧바로 주문 요청으로 연결하지 않습니다.
추천 순서: 공식 예제의 요청 경로·tr_id·필수 파라미터를 API 문서와 대조 → 이 웹앱 백엔드에서 비밀값 없이 재현 → Testbed 응답의 rt_cd·msg_cd 기록 → UI에 필요한 필드만 전달합니다. 예제의 개인 설정 파일·계좌 정보는 저장소에 올리지 않습니다.

LESSON 9 · MCP의 역할과 경계

MCP는 개발 보조 도구이며, 공개 웹앱의 주문 백엔드가 아닙니다

공식 MCP 안내는 API 문서·샘플을 자연어로 찾는 Code Assistant MCP와, 시세·계좌·주문·정정·취소 API를 호출할 수 있는 Trading MCP를 설명합니다. 특히 Trading MCP는 실제 요청을 만들 수 있으므로 개발자의 제한된 로컬 도구로만 사용합니다.

문서 탐색 MCP

“국내주식 모의 현재가 API”, “주문 정정 필수값”처럼 문서·샘플을 찾고 이해하는 데 사용합니다. 찾은 결과는 항상 공식 명세로 재확인합니다.

거래 MCP

계좌·시세·주문성 API를 실행할 수 있습니다. 테스트용 모의 키만, 개발자가 직접 확인하는 세션에서 사용합니다.

웹앱 서버

사용자 요청을 검증한 자체 백엔드만 KIS REST API를 호출합니다. MCP 프로세스를 브라우저 요청의 프록시로 노출하지 않습니다.

금지할 연결: 브라우저의 자연어 입력을 Trading MCP에 그대로 전달하거나, MCP 설정 파일·App Secret을 프론트엔드에 넣거나, 인터넷에 공개된 MCP 서버로 주문 권한을 제공하지 않습니다. MCP와 웹앱은 별도 프로세스·별도 권한·별도 로그로 분리합니다.

LESSON 10 · 모의투자 웹앱 구현 청사진

조회 → 제한된 주문 → 대사 → 실시간을 순서대로 만듭니다

1

설정과 인증을 한 곳에 모읍니다

모의 서버 주소, App Key·Secret, 계좌(CANO-상품코드), 토큰 캐시, 만료 갱신을 서버 전용 KIS 클라이언트가 담당합니다. UI·로그·오류 응답에서는 비밀값과 전체 계좌번호를 제거합니다.

2

조회 API를 먼저 안정화합니다

현재가·일봉·호가·지수·잔고를 각각 시간 제한, 요청 제한, 입력 검증, rt_cd/msg_cd 오류 변환과 함께 만듭니다. 각 API는 단위 테스트와 Testbed 수동 점검을 분리합니다.

3

주문은 확인 가능한 단일 작업으로 시작합니다

로그인, 명시적 확인, 고정된 모의 환경, 수량·가격 상한, 중복 요청 잠금, 주문번호 보관, 정정·취소 결과 확인을 갖춥니다. 현재의 모의 주문 흐름 테스트가 이 단계의 최소 구현입니다.

4

반드시 주문 뒤 대사를 수행합니다

주문 API 응답만 성공으로 보지 말고 미체결·체결 내역과 잔고를 다시 조회해 상태를 맞춥니다. 요청 시각, 종목, 수량, 환경, 결과 코드만 감사 로그로 남기고 키·Secret·토큰은 남기지 않습니다.

5

실시간은 별도 워커로 추가합니다

WebSocket 승인키·구독·재접속·해제·데이터 검증은 별도 서버 워커가 관리합니다. 브라우저는 앱이 만든 WebSocket/SSE만 받고 KIS 자격 증명이나 승인키를 직접 받지 않습니다.

단계완료 기준다음 단계로 가면 안 되는 신호
A. 연결모의 키로 현재가 1건과 오류 메시지를 재현실전 키와 모의 키가 섞였거나, 비밀값이 화면·로그에 보임
B. 조회5개 조회 기능의 입력·제한·실패 처리가 검증됨재시도 폭주, 잔고 화면의 무단 접근, 응답 필드 추측
C. 주문주문 → 정정 → 취소와 후속 조회를 수동 확인중복 방지·취소 확인·감사 로그 없이 자동 주문을 추가
D. 실시간끊김·재접속·구독 해제와 화면 데이터 일관성 확인브라우저에 KIS WebSocket 자격 증명을 노출

KIS 기능을 넓히려면 별도 개발로 다룹니다

주문, 체결 조회, WebSocket 또는 실전 전환은 기존 테스트 모듈의 옵션이 아닙니다. KIS 공식 최신 문서와 샘플을 다시 확인하고, 인증·권한·손실 한도·중복 주문 방지·감사 로그를 포함한 별도 기능으로 설계해야 합니다.
