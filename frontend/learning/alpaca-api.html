Paper Trading 계정을 선택한 뒤 Home 대시보드의 API Keys 패널에서 Paper 계정용 키를 생성합니다. Secret은 재확인이 제한될 수 있으므로 비밀 관리 도구 또는 로컬 .env에만 보관합니다.

SDK 설치 후 계정 조회

4

시세·WebSocket·소액 Paper 주문을 분리 검증

REST는 계정·주문 관리, WebSocket은 시세 및 체결 이벤트 구독에 사용합니다. 주문은 백테스트와 위험 한도를 점검한 뒤 Paper 환경에서만 별도 실행하세요.

ACCOUNT SETUP

Alpaca Paper Trading 계정 생성 과정

아래 순서대로 진행하면 실제 자금을 사용하지 않는 Paper Trading 환경에서 API 연결을 시작할 수 있습니다.

1

회원가입

Alpaca 공식 웹사이트에서 이메일과 비밀번호로 계정을 만들고, 화면에서 요구하는 이메일 확인 또는 본인 확인 절차를 완료합니다. 입력 요구사항은 국가와 계정 유형에 따라 달라질 수 있습니다.

2

Paper Trading 계정 선택 또는 생성

대시보드에서 Paper Trading 계정을 열거나 새 Paper 계정을 생성합니다. 이는 모의 체결 환경이므로 실제 자금이 사용되지 않으며, 전략과 연결 코드를 검증하는 용도입니다.

3

Home의 API Keys 패널에서 Key·Secret 발급

왼쪽의 API 메뉴가 보이지 않아도 됩니다. Home 화면에서 API Keys 패널을 찾아 Paper 계정용 키를 생성합니다. Secret Key는 최초 표시 이후 다시 확인할 수 없을 수 있으므로, 즉시 비밀 관리 도구 또는 로컬 .env에 저장합니다.

4

Python SDK로 연결 확인

키 발급 후에는 주문 전에 get_account()를 실행해 키와 Paper 환경이 정상 연결되는지 먼저 확인합니다. 응답·로그에 Secret을 출력하지 않습니다.

Paper Trading

무료 모의 거래 환경입니다. 실거래소로 주문을 전송하지 않으므로 API·전략·리스크 제어를 먼저 검증하는 데 사용합니다.

Live Trading

실제 거래용 환경입니다. Paper와 API 키·도메인이 다르며, 거주 국가, KYC 심사, 상품 및 규제 요건에 따라 이용 가능 여부가 달라질 수 있습니다.

API Keys 패널이 보이지 않을 때: (1) 문서 사이트가 아닌 Alpaca 대시보드에 로그인했는지, (2) 좌측 상단 계정 선택기가 Paper Trading인지, (3) Home 화면을 새로고침했는지 확인하세요. 계속 없으면 계정 선택기에서 새 Paper 계정을 생성한 후 다시 확인하고 Alpaca Support에 문의하세요.
다음 단계: 계정을 만든 뒤 API 키가 준비되면 이 페이지의 Python SDK 예제로 연결 상태만 먼저 확인하세요. 전략 백테스트와 리스크 한도를 확인하기 전에는 Live Trading으로 전환하지 않습니다.

NAME CHECK

이 문서의 Alpaca와 다른 동명 프로젝트를 구분하세요

Alpaca Markets

이 실전연습에서 다루는 금융 트레이딩 API 플랫폼입니다. 공식 Trading CLI와 alpaca-py를 사용하며, Paper Trading을 기본으로 연습합니다.

Stanford Alpaca

Stanford 연구진이 공개한 instruction-following LLM 연구 프로젝트입니다. 금융 트레이딩 API가 아니며, 로컬 실행은 선택한 LLM 런타임과 해당 모델 배포 조건을 별도로 확인해야 합니다.

Alpacon / AlpacaX

서버·GPU 인프라 운영을 위한 별도 제품군입니다. Alpaca Markets와 계정·키·CLI가 공유되지 않으며, 이 문서의 Paper Trading 설정과 관계없습니다.

안전한 선택

주식·암호화폐 Paper Trading 자동화가 목적이라면 Alpaca Markets Trading CLI 또는 alpaca-py만 사용하세요. 다른 동명 CLI에 금융 API 키를 입력하지 마세요.

1

연결·조회

Paper 연결·조회에서 계정 상태, 포지션, 최근 주문 내역, 미국 장 상태, AAPL 같은 티커의 최근 호가·체결을 조회합니다. Key·Secret·계좌번호·잔고는 화면에 반환하지 않습니다.

2

보호된 주문 흐름 점검

Paper 주문 흐름 테스트는 로그인과 체크 확인 뒤 AAPL 1주를 $1.00의 고정 비시장성 지정가로 접수하고 즉시 취소합니다. AAPL 매도호가가 $2 이하이거나 취소에 실패하면 안전하게 중단·알림 처리합니다.

3

주문 후 대사

주문 응답만 믿지 않고 최근 주문 내역·포지션을 다시 조회해 취소 상태를 확인합니다. 확장 구현에서는 사용자별 접근 통제, 요청 중복 방지, 감사 로그, WebSocket 주문 이벤트를 추가해야 합니다.

주의사항

Paper 결과를 실거래 결과로 간주하지 않습니다

키 보안: API Key·Secret을 HTML, 브라우저 JavaScript, 화면 캡처, Git, 메시지에 넣지 마세요. 유출이 의심되면 대시보드에서 즉시 폐기·재발급합니다.
시뮬레이션 한계: Paper Trading은 실제 주문을 거래소로 전송하지 않는 시뮬레이션입니다. 시장 충격, 지연에 따른 슬리피지, 지정가 주문의 호가 대기 순서 등은 실거래와 다를 수 있습니다. 기본 시장 데이터 범위도 계정 플랜에 따라 제한될 수 있습니다.
국가별 이용 가능 여부: Paper 전용 계정은 전 세계에서 생성 가능하다고 Alpaca가 안내하지만, 실거래 계정의 승인·상품·세금·규제 요건은 거주 국가와 심사에 따라 달라집니다. 한국 거주자의 실거래 가능 여부를 코드에서 가정하지 말고 신청 시점의 공식 안내를 확인하세요.

안전한 주문 흐름의 기능

  1. 로그인과 체크 확인이 있어야 요청할 수 있다.
  2. Paper 엔드포인트만 사용한다.
  3. AAPL 1주와 고정된 낮은 지정가로 비시장성 주문을 시도한다.
  4. 가격 안전 조건을 만족할 때만 요청한다.
  5. 주문 식별자·Secret·Token은 화면에 노출하지 않는다.
  6. 주문 직후 취소를 요청하며, 취소 실패 시 대시보드에서 미체결 주문을 확인한다.

역할 분담

  • 계정 담당: Paper/Live 분리와 Key 발급 상태를 확인한다.
  • 데이터 담당: /account, /positions, /orders, /clock, 시장 데이터 결과를 해석한다.
  • 주문 담당: 확인 문구·수량·가격 제한·자동 취소가 유지되는지 점검한다.
  • 감사 담당: 주문 응답만 보지 않고 주문 내역·포지션으로 후속 대사를 확인한다.

TradingView(Pine) 학습/learning/tradingview-pine.html전략 설계 담당지표(indicator)와 가상 주문 전략(strategy)의 차이를 설명한다.
Pine 간단 테스트/pine-script-lab.html에서 MA·RSI 예제를 수정조건 검증 담당기간을 하나만 변경해 신호 수·단순 수익률·MDD 변화만 비교한다.
Pine 전략 모의주문/trade/pine.html앱 모의주문 담당이 웹앱의 모의주문과 Alpaca Paper 주문은 서로 다른 장부임을 확인한다.
최종 검증TradingView Pine Editor백테스트 검토 담당실제 종목·시간봉·수수료·슬리피지를 넣은 Strategy Report로 재검증한다.

구현 관점: Pine 간단 테스트는 제한된 문법의 교육용 계산기다. 웹훅·API Key·계좌 정보를 Pine 코드 또는 브라우저에 넣지 않으며, 자동매매 연결은 주문 중복 방지·손실 한도·감사 로그가 갖춰진 별도 서버에서만 검토한다.

준비·설정 상세 (이 저장소 기준)

키 저장 위치·우선순위와 기동 전 체크리스트는 01.md의 "준비·설정 상세"를 따른다. Alpaca는 al.key 또는 .env의 ALPACA_API_KEY/ALPACA_SECRET_KEY를 사용하며, 환경변수가 둘 다 있으면 환경변수가 우선한다. Paper 도메인은 코드에 고정되어 있어 Live로 전환되는 설정은 없다.

사전 가입·발급 절차 (오전 실습 상세)

순서할 일어디서결과물
1이메일 가입 후 이메일 확인https://app.alpaca.markets/signupAlpaca 계정
2대시보드 좌측 상단 계정 선택기에서 Paper Trading 선택/생성https://app.alpaca.markets/account/loginPaper 계정
3Home → API Keys에서 Paper 키 생성. Secret은 재표시되지 않을 수 있다.대시보드Paper Key·Secret
4al.key 작성 (위 형식), 권한 600저장소 루트파일 준비 완료
  • 키 파일 파서는 Key/api_key/apca_api_key_id, Secret/secret_key/apca_api_secret_key 이름을 모두 허용한다.
  • Paper 전용 계정은 거주 국가와 무관하게 별도 심사 없이 만들 수 있다. Live 계정 승인·세금 서류는 과정 범위 밖이다.
  • Paper 키를 Live 도메인에, Live 키를 Paper 도메인에 넣으면 401이 난다. 코드는 Paper 도메인 고정이라 Live 키를 넣어도 Live 주문은 나가지 않는다.
  • 저장소 루트의 alpaca-re.key는 Alpaca 키 형식이 아닌 별도 식별자이며 코드가 읽지 않는다.
