Secrets Manager 사용 구조

Flask 서버는 boto3의 Secrets Manager 클라이언트를 만들고, 서비스 이름에 맞는 JSON 보안 암호를 조회합니다. 로컬에서는 AWS CLI 프로필을 사용하고 EC2에서는 인스턴스 Role을 사용하므로 애플리케이션 소스에 AWS Access Key를 저장할 필요가 없습니다.

client = boto3.client("secretsmanager", region_name=region) response = client.get_secret_value(SecretId="stock-coin-trade/kis") credentials = json.loads(response["SecretString"])
브라우저 → Flask API → aws_secret_store.py → boto3 Secrets Manager → 브로커 읽기 API
  • AWS_REGION은 사용할 리전을, AWS_SECRETS_MANAGER_PREFIX는 Secret 이름의 공통 접두사를 지정합니다.
  • DescribeSecret으로 존재 여부와 변경 시각을 확인하고 GetSecretValue로 JSON을 읽습니다.
  • 브로커별 필수 필드가 모두 있는지 확인한 뒤 읽은 JSON을 서버 메모리에 최대 5분간 캐시합니다.
  • 브라우저에는 준비 여부와 누락 필드만 반환하며 App Key, Secret, 계좌번호는 반환하지 않습니다.

처음 구축하거나 다시 구축하는 방법

1. 환경 이름 설정

AWS_REGION=ap-northeast-2 AWS_SECRETS_MANAGER_PREFIX=stock-coin-trade # 고객 관리형 KMS 키를 쓸 때만 설정 # AWS_SECRETS_MANAGER_KMS_KEY_ID=<KMS key ARN>

2. 업로드 담당자 권한 연결

AWS 콘솔에서 업로드에 사용할 사용자 또는 Role에 aws/iam/secrets-manager-provisioner-policy.json을 인라인 정책으로 연결합니다.

AWS 콘솔 → IAM → 사용자 또는 역할 → 권한 추가 → 인라인 정책 생성 → JSON → secrets-manager-provisioner-policy.json 붙여넣기

3. 값 없이 미리보기

python python-stock-backend/upload_keys_to_secrets_manager.py \ --profile sagemaker-admin --region ap-northeast-2

kis, kb, alpaca가 모두 READY인지 확인합니다. 이 명령은 AWS를 변경하지 않으며 키 값을 출력하지 않습니다.

4. 실제 생성

python python-stock-backend/upload_keys_to_secrets_manager.py \ --profile sagemaker-admin --region ap-northeast-2 --apply

5. 기존 Secret의 키 교체

python python-stock-backend/upload_keys_to_secrets_manager.py \ --profile sagemaker-admin --region ap-northeast-2 \ --apply --overwrite --only kis
--overwrite는 기존 Secret에 새 버전을 추가합니다. 처음 생성할 때는 사용하지 않고, 실제 키 회전이 필요할 때만 사용합니다.

앱에서 사용하는 방법

로컬 Docker

AWS CLI 프로필을 컨테이너에 전달하는 전용 override를 함께 사용합니다.

AWS_PROFILE=sagemaker-admin docker compose \ -f docker-compose.yml \ -f docker-compose.aws-profile.yml \ up -d --build python-backend frontend

EC2 운영 환경

EC2 인스턴스 Role에 secrets-manager-runtime-policy.json을 연결하고 기본 Compose 파일로 실행합니다. 운영 서버에는 장기 Access Key나 로컬 AWS 프로필을 복사하지 않습니다.

docker compose up -d --build python-backend frontend

런타임 Role은 stock-coin-trade/*에 대한 아래 두 권한만 갖습니다.

secretsmanager:DescribeSecret secretsmanager:GetSecretValue

고객 관리형 KMS 키를 선택한 경우에만 그 KMS 키의 kms:Decrypt를 추가합니다.

오류 해결과 운영 원칙

  • AccessDeniedException: 생성 담당자는 Create/Update, 앱 Role은 Describe/Get 권한이 있는지 구분합니다. IAM 정책 반영에는 잠시 시간이 걸릴 수 있습니다.
  • ResourceNotFoundException: AWS 계정, 서울 리전, AWS_SECRETS_MANAGER_PREFIX가 생성 시점과 같은지 확인합니다.
  • ResourceExistsException: 같은 이름이 이미 있습니다. 키 회전이 맞을 때만 --overwrite를 사용합니다.
  • 필드 누락: 상태 응답의 missingFields를 확인하고 원본 키 파일의 필드명을 점검합니다.
  • 브로커 인증 실패: Secrets Manager가 3/3이면 Paper/실전 키 종류, 계좌 형식, 브로커 측 활성 상태를 확인합니다.
  • 앱 Role에는 Secret 생성·갱신·삭제 권한을 주지 않으며, 키 원문을 Git·README·Dockerfile·명령 인자에 넣지 않습니다.
