이 웹앱의 AWS 트랙은 EC2 디스크의 kis.key·kb.key·al.key를 읽지 않습니다. 서버 IAM 역할이 SSM Parameter Store에서 필요한 값만 읽고, 브라우저에는 키·Secret·토큰을 보내지 않습니다.

어떤 AWS 리소스를 쓰나요?

SSM Parameter Store

환경별 이름·엔드포인트·계좌번호와 SecureString 값을 계층 경로로 관리합니다. 이 앱은 5분 메모리 캐시를 사용해 불필요한 조회를 줄입니다.

AWS KMS

SecureString 값을 암호화·복호화합니다. 운영에서는 고객 관리형 KMS 키와 kms:ViaService 조건을 권장합니다.

IAM Role · CloudTrail

EC2 인스턴스 프로파일에 최소 권한을 부여하고, 누가 파라미터를 조회·수정했는지는 CloudTrail에서 감사합니다.

선택 기준: API Key·Secret처럼 회전과 감사 요구가 큰 비밀은 AWS가 권장하는 Secrets Manager도 검토하세요. 현재 앱은 Parameter Store SecureString을 사용하며, 두 서비스를 동시에 같은 키 원본으로 사용하지 않습니다.

최소 권한 IAM 정책의 핵심

실제 리전·계정 ID·KMS 키 ARN으로 바꿔 적용하세요. 애플리케이션에는 쓰기·삭제·경로 전체 조회 권한을 주지 않습니다.

ssm:GetParameter, ssm:GetParameters
Resource: arn:aws:ssm:<region>:<account-id>:parameter/stock-coin-trade/*

kms:Decrypt
Resource: <customer-managed-kms-key-arn>
Condition: kms:ViaService = ssm.<region>.amazonaws.com
상위 경로에 GetParametersByPath 권한을 주면 하위 항목까지 함께 읽힐 수 있습니다. 이 앱은 개별 이름 조회를 사용하므로 필요한 정확한 경로만 허용하세요.

운영 체크리스트

① EC2에는 액세스 키를 파일·환경변수로 넣지 말고 인스턴스 프로파일을 사용합니다. ② 개발·스테이징·운영은 서로 다른 접두사와 KMS 키를 사용합니다. ③ 파라미터 이름에 계좌번호·비밀값을 넣지 않습니다. ④ 키 교체 뒤에는 Parameter Store의 버전과 CloudTrail 이벤트를 확인합니다. ⑤ 자동 회전이 필요한 키는 Secrets Manager 전환을 검토합니다.
