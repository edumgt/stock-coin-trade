# 4일차 — Binance·Korbit 공개 API와 통합 운영 점검

## 과정 개요

- 권장 분량: 6시간 (오전 3시간 / 오후 3시간)
- 대상: 가상자산 공개 API의 데이터 구조와 안전한 개인 API 확장 원칙을 배우려는 학습자
- 목표: Binance Spot과 Korbit 공개 시세·호가 API를 키 없이 호출하고, KIS·KB·Alpaca·거래소 모듈의 권한 경계를 비교한다.
- 산출물: 양 거래소 공개 API 점검 기록, 개인 API 권한 설계표, 4일차 종합 체크리스트

> 공개 시세 API는 가입·키 없이 시작할 수 있다. 개인 잔고·주문·입출금 API는 API Key, 서명, 권한이 필요하며 이 과정에서 실행하지 않는다.

| 목적 | Binance | Korbit | 허용 여부 |
|---|---|---|---|

| 개인 잔고 조회 | 별도 조회 권한·서명 | 자산 조회 권한·서명 | 별도 설계 후 검토 |

| 출금 | 사용하지 않음 | 출금 조회/신청 권한 부여 금지 | 과정 금지 |

### 연계 실습 — AI Sheet·Quant·에러분석 (60분)

마지막 날에는 시세 응답을 단순 표시하는 데서 끝내지 않고, 분석 결과의 재현성과 운영 오류 대응을 함께 연습한다. 공개 API라 해도 호출 실패와 데이터 지연은 발생할 수 있다.

| 기능 | 구현·사용 순서 | 역할 | 확인 항목 |
|---|---|---|---|
| AI Sheet | `/ai-sheet.html` | 조사·요약 담당 | 근거 링크와 요약을 분리해 기록하고, API Key·계좌번호를 입력하지 않는다. |
| PostgreSQL Quant | `/quant.html?tab=simulation` | 전략 검증 담당 | OHLCV·전략·체결·성과 지표가 분리된 구조와 백테스트 가정을 확인한다. |
| 에러분석 | `/error-analysis.html` | 운영·장애 대응 담당 | 서버 4xx/5xx와 브라우저 오류의 발생 시각·경로·원인 설명·마스킹된 스택을 읽는다. |
| 오류 재현 기록 | 공개 API 테스트에서 잘못된 심볼을 한 번만 입력 | 품질 담당 | HTTP 상태, 재현 절차, 기대/실제 결과를 기록하고 무한 재시도는 하지 않는다. |

**구현 관점:** `system_error_log`는 서버와 브라우저 오류를 통합하되 토큰·비밀번호·API Key를 마스킹한다. 전체 로그 열람은 관리자 전용이며, 오류 상세에는 해결에 필요한 경로·상태·스택만 남긴다. 분석 결과도 외부 API의 일시 오류와 데이터 공급 지연을 고려해 재실행 가능하게 설계한다.
