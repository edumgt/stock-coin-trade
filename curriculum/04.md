# Binance·Korbit 공개 API와 통합 운영 점검

## 과정 개요

- 대상: 가상자산 공개 API의 데이터 구조와 안전한 개인 API 확장 원칙을 배우려는 학습자
- 목표: Binance Spot과 Korbit 공개 시세·호가 API를 키 없이 호출하고, KIS·KB·Alpaca·거래소 모듈의 권한 경계를 비교한다.
- 산출물: 양 거래소 공개 API 점검 기록, 개인 API 권한 설계표, 통합 체크리스트

> 공개 시세 API는 가입·키 없이 시작할 수 있다. 개인 잔고·주문·입출금 API는 API Key, 서명, 권한이 필요하며 이 과정에서 실행하지 않는다.

## 개인 API 키 최소 권한 원칙

| 목적 | Binance | Korbit | 허용 여부 |
|---|---|---|---|
| 공개 시세·호가 | Key 불필요 | Key 불필요 | 현재 웹앱에서 제공 |
| 개인 잔고 조회 | 별도 조회 권한·서명 | 자산 조회 권한·서명 | 별도 설계 후 검토 |
| 주문·취소 | 거래 권한·서명·Testnet 우선 | 주문 조회/신청 권한·서명 | 별도 명시적 승인 후 |
| 출금 | 사용하지 않음 | 출금 조회/신청 권한 부여 금지 | 과정 금지 |

## 공개 API 경로와 기능

### 이 웹앱의 공개 API 경로

```text
GET /api/crypto-exchange-test/binance/ticker?symbol=BTCUSDT
GET /api/crypto-exchange-test/binance/orderbook?symbol=BTCUSDT
GET /api/crypto-exchange-test/korbit/ticker?symbol=btc_krw
GET /api/crypto-exchange-test/korbit/orderbook?symbol=btc_krw
```

| 모듈 | 환경 | 현재 웹앱 기능 | 주문성 기능 |
|---|---|---|---|

### 연계 기능 — AI Sheet·Quant·에러분석

시세 응답을 단순 표시하는 데서 끝내지 않고, 분석 결과의 재현성과 운영 오류 대응을 함께 연습한다. 공개 API라 해도 호출 실패와 데이터 지연은 발생할 수 있다.

| 기능 | 구현·사용 순서 | 역할 | 확인 항목 |
|---|---|---|---|
| AI Sheet | `/ai-sheet.html` | 조사·요약 담당 | 근거 링크와 요약을 분리해 기록하고, API Key·계좌번호를 입력하지 않는다. |
| PostgreSQL Quant | `/quant.html?tab=simulation` | 전략 검증 담당 | OHLCV·전략·체결·성과 지표가 분리된 구조와 백테스트 가정을 확인한다. |
| 에러분석 | `/error-analysis.html` | 운영·장애 대응 담당 | 서버 4xx/5xx와 브라우저 오류의 발생 시각·경로·원인 설명·마스킹된 스택을 읽는다. |
| 오류 재현 기록 | 공개 API 테스트에서 잘못된 심볼을 한 번만 입력 | 품질 담당 | HTTP 상태, 재현 절차, 기대/실제 결과를 기록하고 무한 재시도는 하지 않는다. |

**구현 관점:** `system_error_log`는 서버와 브라우저 오류를 통합하되 토큰·비밀번호·API Key를 마스킹한다. 전체 로그와 오류 상세는 로그인 회원이 열람할 수 있으며, 해결에 필요한 경로·상태·마스킹된 스택만 제공한다. 분석 결과도 외부 API의 일시 오류와 데이터 공급 지연을 고려해 재실행 가능하게 설계한다.

## 준비·설정 상세 (이 저장소 기준)

### 사전 가입·준비

| 대상 | 가입·키 | 준비할 것 |
|---|---|---|
| Binance Spot 공개 API | **불필요** | 없음. `BTCUSDT` 심볼 규칙만 숙지 |
| Korbit 공개 API | **불필요** | 없음. `btc_krw` 거래쌍 규칙만 숙지 |
| Binance 개인 API (과정 밖) | 가입 + API Key·Secret + HMAC SHA-256 서명 + IP 화이트리스트 | 실습 시 운영 키 대신 Spot Testnet(<https://testnet.binance.vision>) 별도 계정·키 사용 |
| Korbit 개인 API (과정 밖) | 가입 + 본인 인증 + API Key(자산 조회 / 주문 조회 / 주문 신청 / 입출금 조회·신청 권한 개별 선택) | 출금 권한은 절대 부여하지 않음 |

이 저장소에는 두 거래소의 개인 API 구현이나 인증 환경변수가 **없다**. 최소 권한표는 문서 안내이며 실제 키 생성은 하지 않는다.

### 호출 대상

| 웹앱 API | 거래소 경로 | 인증 |
|---|---|---|
| `GET /api/crypto-exchange-test/binance/ticker?symbol=BTCUSDT` | `https://api.binance.com/api/v3/ticker/24hr` | 없음 |
| `GET /api/crypto-exchange-test/binance/orderbook?symbol=BTCUSDT` | `https://api.binance.com/api/v3/depth?limit=10` | 없음 |
| `GET /api/crypto-exchange-test/korbit/ticker?symbol=btc_krw` | `https://api.korbit.co.kr/v2/tickers` | 없음 |
| `GET /api/crypto-exchange-test/korbit/orderbook?symbol=btc_krw` | `https://api.korbit.co.kr/v2/orderbook` | 없음 |

- Binance는 IP 단위 가중치 기반 호출 제한(HTTP 429/418)이 있다. 교육장에서 여러 학습자가 같은 공인 IP를 쓰면 한 사람의 폴링이 전체를 차단시킬 수 있으니 "호출 제한 점검" 항목에서 강조한다.
- 접속 지역에 따라 `api.binance.com`이 차단될 수 있다. 실습 전 서버에서 `curl https://api.binance.com/api/v3/ping`으로 확인한다.
- 연계 기능에 필요한 서버 측 설정: PostgreSQL(`COMPOSE_PROFILES=local-db` 또는 `QUANT_DATABASE_URL`), 선택적으로 `ANTHROPIC_API_KEY`(<https://console.anthropic.com>), `CMC_API_KEY`(<https://coinmarketcap.com/api/>, 코인 랭킹 동기화용, 없어도 동작).

### 통합 운영 점검 확장: AWS Secrets Manager 트랙

로컬 `.env` 대신 AWS Secrets Manager의 JSON 보안 암호에서 키를 읽는 **별도 트랙**이다. URL·모듈이 분리되어 있으며 EC2 운영 환경에서는 인스턴스 Role로 보안 암호를 읽는다.

| 항목 | 내용 |
|---|---|
| 코드 | [aws_secret_store.py](../python-stock-backend/aws_secret_store.py), [broker_test_aws.py](../python-stock-backend/broker_test_aws.py), [alpaca_test_aws.py](../python-stock-backend/alpaca_test_aws.py) |
| API | `/api/aws-broker-test/secrets/status`, `/kis/quote`, `/kis/balance`, `/kb/token`, `/kb/quote`, `/api/aws-alpaca-test/paper/account`, `/positions`, `/clock`, `/asset` (모두 읽기 전용, 주문 없음) |
| 화면 | `/aws-broker-api-test.html`, `/aws-alpaca-test.html`, `/learning/aws-ssm-key-management.html` |
| 환경변수 | `AWS_REGION`, `AWS_SECRETS_MANAGER_PREFIX`(기본 `stock-coin-trade`), 로컬 개발 시 `AWS_PROFILE`, EC2에서는 인스턴스 Role |
| 보안 암호 이름 | `stock-coin-trade/kis`(JSON 필드 3개), `stock-coin-trade/kb`(2개), `stock-coin-trade/alpaca`(2개) |
| 사전 준비 | IAM에 `secretsmanager:DescribeSecret`, `secretsmanager:GetSecretValue` 최소 권한. EC2는 인스턴스 프로파일 권장 |
| 참고 | README "Secrets Manager 트랙", <https://docs.aws.amazon.com/secretsmanager/latest/userguide/intro.html> |

### 제출물에서 마스킹해야 하는 항목

App Key, App Secret, Access Token, 계좌번호(CANO·상품코드 포함), HTS ID, Alpaca 주문 ID, `.env` 전체, `.vscode/mcp.json`의 계좌 입력값.

### 진행자 사전 점검 명령

```bash
curl -s https://api.binance.com/api/v3/ping
curl -s 'http://localhost:3333/api/crypto-exchange-test/binance/ticker?symbol=BTCUSDT'
curl -s 'http://localhost:3333/api/crypto-exchange-test/korbit/ticker?symbol=btc_krw'
# 통합 점검: 비밀 파일이 Git에 잡히지 않는지 (출력이 비어야 정상)
git ls-files | grep -E '\.key$|\.pem$|\.env$|^mcp/|^\.vscode/'
```
