# 1일차 — KIS Testbed 시작과 모의 주문 흐름

## 과정 개요

- 권장 분량: 6시간 (오전 3시간 / 오후 3시간)
- 대상: 국내주식 Open API를 처음 사용하는 학습자
- 목표: 한국투자증권 모의투자 계좌·KIS Developers 모의 키를 준비하고, 이 웹앱에서 조회 및 보호된 모의 주문 흐름을 이해한다.
- 산출물: 개인별 `kis.key` 설정 완료, KIS 연결·조회 점검표, 모의 주문 흐름 결과 기록

> 이 과정은 KIS Testbed만 사용한다. 실전 계좌·실전 App Key·실전 주문은 과정 범위에 포함하지 않는다.

## 오전 — 공식 사이트 가입·신청·키 준비 (3시간)

| 시간 | 학습자 활동 | 진행자/조교 역할 | 완료 기준 |
|---|---|---|---|
| 09:00–09:30 | KIS, 이 웹앱 계정, 한국투자증권 계정의 역할을 구분한다. | 입력 위치와 비밀정보 취급 원칙을 설명한다. | 어떤 계정에 무엇을 입력하는지 설명할 수 있다. |
| 09:30–10:20 | 한국투자증권 고객 ID·계좌 상태를 확인하고, 공식 모의투자 참가 신청을 진행한다. | 신청 화면의 최신 약관·계좌 확인만 지원한다. | 모의투자 전용 계좌번호를 확인한다. |
| 10:30–11:20 | KIS Developers에서 모의투자 계좌로 API 서비스를 신청한다. | 실전/모의 행과 Key·Secret의 짝을 확인시킨다. | 모의 App Key와 App Secret이 발급된다. |
| 11:20–12:00 | 서버의 `kis.key`를 작성하고 Git 제외 여부를 확인한다. | 키를 화면·채팅·Git에 남기지 않도록 점검한다. | 파일 형식이 유효하고 파일 권한을 확인한다. |

```ini
# 프로젝트 루트의 kis.key — 모의투자 값만 사용
app_key=모의_App_Key
secret=모의_App_Secret
account=12345678-01
```

### 오전 핵심 개념

1. `account`의 하이픈 앞은 CANO, 뒤는 계좌상품코드다. 임의로 `-01`, `-02`를 바꾸지 않는다.
2. 시세·호가·차트에는 키가 필요하고, 잔고·주문성 기능에는 계좌 설정도 필요하다.
3. `kis.key`는 컨테이너 안에서 `/run/secrets/kis.key`로 읽기 전용 전달된다.
4. 공식 구현·샘플의 기준은 <https://github.com/koreainvestment/open-trading-api>다.

## 오후 — KIS 실전연습 + 기본 자산관리 흐름 (3시간)

| 순서 | 웹앱 기능 | 역할 | 확인할 결과 |
|---|---|---|---|
| 1 | `/broker-api-test.html` 또는 KIS 연결 테스트 | 연결 검증자 | 현재가 1건이 정상 반환된다. |
| 2 | KIS 조회 API | 데이터 검증자 | 현재가, 일봉, 10단계 호가, 코스피/코스닥 지수의 차이를 설명한다. |
| 3 | 잔고·평가액 조회 | 보안 점검자 | 로그인·접근 통제 필요성을 확인한다. |
| 4 | `/kis-order-flow-test.html` | 주문 흐름 관찰자 | 모의 주문 → 정정 → 취소의 결과를 확인한다. |
| 5 | 결과 정리 | 기록 담당 | 시각, 종목, 환경, 성공/실패 코드만 기록한다. |

### API 실습 범위

```text
GET  /api/broker-test/kis/quote?symbol=005930
GET  /api/broker-test/kis/chart?symbol=005930
GET  /api/broker-test/kis/orderbook?symbol=005930
GET  /api/broker-test/kis/index?code=0001
GET  /api/broker-test/kis/balance
POST /api/broker-test/kis/order-flow-test   # 로그인·확인 필요
```

### 오후 토의: 역할과 안전장치

- 프론트엔드 역할: 종목코드 검증, 사용자 확인, 결과 표시. Key·Secret을 절대 받지 않는다.
- 백엔드 역할: Testbed 토큰 발급·캐시, KIS 호출, 안전한 오류 변환, 주문 흐름 잠금.
- 운영자 역할: 모의 키의 만료·해지 상태, Docker Secret mount, 접근 로그를 관리한다.
- 학습자 역할: 자동 반복 호출을 하지 않고, 주문성 테스트는 확인 문구를 읽고 한 번씩 실행한다.

### 연계 실습 — 회원·대시보드·보유자산 (60분)

KIS 호출 결과를 API 화면에서만 끝내지 않고, 이 웹앱의 기본 사용자 흐름과 연결한다. 외부 증권사 계좌와 이 웹앱의 학습용 자산은 서로 다른 데이터라는 점을 확인하는 것이 목적이다.

| 기능 | 구현·사용 순서 | 역할 | 확인 항목 |
|---|---|---|---|
| 회원가입·로그인 | `/member/register.html` → `/member/login.html` | 사용자 인증 | 세션이 있어야 개인 보유자산·주문 기능에 접근할 수 있음을 확인한다. |
| 대시보드 | `/index.html` | 시장 요약 화면 | 코인·주식 요약 시세와 KIS 외부 시세 조회 결과가 같은 데이터 소스가 아닐 수 있음을 기록한다. |
| 보유자산 | `/trade/hold.html` | 학습용 포트폴리오 | 현금·주식·코인·대체자산의 평가액을 확인한다. KIS 실계좌 잔고를 복사하거나 동기화하지 않는다. |
| 포트폴리오 분석 | 보유자산 화면의 분석 기능 | 위험 점검 | 자산군 비중·집중도·레버리지 노출을 읽고, API 키와 자산 정보의 접근 권한을 분리한다. |

**구현 관점:** 회원 세션은 개인 학습 데이터의 접근을 제어하고, KIS Key는 서버의 Secret mount에서만 사용한다. 프런트엔드에 Key를 전달하거나 브라우저 저장소에 보관하지 않는다.

## 제출·평가

- `kis.key` 값은 제출하지 않는다. 대신 키 이름·계좌 형식만 마스킹한 체크 결과를 제출한다.
- 조회 API 2개 이상 성공 화면 또는 성공 코드 기록을 제출한다.
- 주문 흐름은 성공 여부와 관계없이 “주문 후 취소 확인이 왜 필요한가”를 3문장으로 정리한다.
