# KIS Testbed 시작과 모의 주문 흐름

## 과정 개요

- 대상: 국내주식 Open API를 처음 사용하는 학습자
- 목표: 한국투자증권 모의투자 계좌·KIS Developers 모의 키를 준비하고, 이 웹앱에서 조회 및 보호된 모의 주문 흐름을 이해한다.
- .env.example 을 복사한뒤 해당 값 입력 후 .env 으로 저장
- 산출물: 개인별 `.env` 설정 완료, KIS 연결·조회 점검표, 모의 주문 흐름 결과 기록

> 이 과정은 KIS Testbed만 사용한다. 실전 계좌·실전 App Key·실전 주문은 과정 범위에 포함하지 않는다.

## 오전 — 공식 사이트 가입·신청·키 준비 (3시간)

| 시간 | 학습자 활동 | 진행자/조교 역할 | 완료 기준 |
|---|---|---|---|
| 09:00–09:30 | KIS, 이 웹앱 계정, 한국투자증권 계정의 역할을 구분한다. | 입력 위치와 비밀정보 취급 원칙을 설명한다. | 어떤 계정에 무엇을 입력하는지 설명할 수 있다. |
| 09:30–10:20 | 한국투자증권 고객 ID·계좌 상태를 확인하고, 공식 모의투자 참가 신청을 진행한다. | 신청 화면의 최신 약관·계좌 확인만 지원한다. | 모의투자 전용 계좌번호를 확인한다. |
| 10:30–11:20 | KIS Developers에서 모의투자 계좌로 API 서비스를 신청한다. | 실전/모의 행과 Key·Secret의 짝을 확인시킨다. | 모의 App Key와 App Secret이 발급된다. |
| 11:20–12:00 | 서버의 `.env`를 작성하고 Git 제외 여부를 확인한다. | 키를 화면·채팅·Git에 남기지 않도록 점검한다. | 파일 형식이 유효하고 파일 권한을 확인한다. |

```ini
# 프로젝트 루트의 .env — 모의투자 값만 사용
KIS_PAPER_APP_KEY=모의_App_Key
KIS_PAPER_APP_SECRET=모의_App_Secret
KIS_PAPER_ACCOUNT_NO=12345678-01
```

### 오전 핵심 개념

1. `KIS_PAPER_ACCOUNT_NO`의 하이픈 앞은 CANO, 뒤는 계좌상품코드다. 임의로 `-01`, `-02`를 바꾸지 않는다.
2. 시세·호가·차트에는 키가 필요하고, 잔고·주문성 기능에는 계좌 설정도 필요하다.
3. Docker Compose가 `.env` 값을 컨테이너 환경변수로 전달하며 파일 자체는 마운트하지 않는다.
4. 공식 구현·샘플의 기준은 <https://github.com/koreainvestment/open-trading-api>다.

### CANO와 계좌상품코드

CANO는 한국투자증권(KIS) OpenAPI에서 쓰는 필드명으로, 종합계좌번호(Comprehensive Account NO.)의 약자다. KIS 계좌번호는 `12345678-01` 형태이고, API 요청 시 두 부분으로 나눠 보낸다.

| 위치 | 필드명 | 의미 | 자릿수 |
|---|---|---|---|
| 하이픈 앞 | `CANO` | 종합계좌번호 (고객 계좌 식별) | 8자리 |
| 하이픈 뒤 | `ACNT_PRDT_CD` | 계좌상품코드 (계좌 종류) | 2자리 |

계좌상품코드는 계좌 개설 시 증권사가 부여한 값이라 사용자가 고를 수 없다. 예를 들어 01은 종합/위탁 계좌, 03은 선물옵션 계좌, 22는 연금 계좌처럼 종류마다 정해져 있다. "01이 안 되니 02로 바꿔 보자" 식으로 임의 수정하면 KIS 서버가 계좌를 찾지 못해 조회와 주문이 모두 실패한다.

| 순서 | 웹앱 기능 | 역할 | 확인할 결과 |

| 2 | KIS 조회 API | 데이터 검증자 | 현재가, 일봉, 10단계 호가, 코스피/코스닥 지수의 차이를 설명한다. |

| 4 | `/kis-order-flow-test.html` | 주문 흐름 관찰자 | 모의 주문 → 정정 → 취소의 결과를 확인한다. |

### API 실습 범위

```text
GET  /api/broker-test/kis/quote?symbol=005930
GET  /api/broker-test/kis/chart?symbol=005930
GET  /api/broker-test/kis/orderbook?symbol=005930
GET  /api/broker-test/kis/index?code=0001
GET  /api/broker-test/kis/balance
POST /api/broker-test/kis/order-flow-test   # 로그인·확인 필요
```

### 오후 토의: 역할과 안전장치

- 프론트엔드 역할: 종목코드 검증, 사용자 확인, 결과 표시. Key·Secret을 절대 받지 않는다.
- 백엔드 역할: Testbed 토큰 발급·캐시, KIS 호출, 안전한 오류 변환, 주문 흐름 잠금.
- 운영자 역할: 모의 키의 만료·해지 상태, `.env` 권한, 접근 로그를 관리한다.
- 학습자 역할: 자동 반복 호출을 하지 않고, 주문성 테스트는 확인 문구를 읽고 한 번씩 실행한다.

### 연계 실습 — 회원·대시보드·보유자산 (60분)

KIS 호출 결과를 API 화면에서만 끝내지 않고, 이 웹앱의 기본 사용자 흐름과 연결한다. 외부 증권사 계좌와 이 웹앱의 학습용 자산은 서로 다른 데이터라는 점을 확인하는 것이 목적이다.

| 기능 | 구현·사용 순서 | 역할 | 확인 항목 |
|---|---|---|---|
| 회원가입·로그인 | `/member/register.html` → `/member/login.html` | 사용자 인증 | 세션이 있어야 개인 보유자산·주문 기능에 접근할 수 있음을 확인한다. |
| 대시보드 | `/index.html` | 시장 요약 화면 | 코인·주식 요약 시세와 KIS 외부 시세 조회 결과가 같은 데이터 소스가 아닐 수 있음을 기록한다. |
| 보유자산 | `/trade/hold.html` | 학습용 포트폴리오 | 현금·주식·코인·대체자산의 평가액을 확인한다. KIS 실계좌 잔고를 복사하거나 동기화하지 않는다. |
| 포트폴리오 분석 | 보유자산 화면의 분석 기능 | 위험 점검 | 자산군 비중·집중도·레버리지 노출을 읽고, API 키와 자산 정보의 접근 권한을 분리한다. |

**구현 관점:** 회원 세션은 개인 학습 데이터의 접근을 제어하고, KIS Key는 서버 환경변수에서만 사용한다. 프런트엔드에 Key를 전달하거나 브라우저 저장소에 보관하지 않는다.

## 준비·설정 상세 (이 저장소 기준)

### 인증정보 저장 위치

| 모듈 | `.env` 변수 | 전달 방식 |
|---|---|---|
| KIS | `KIS_PAPER_APP_KEY`, `KIS_PAPER_APP_SECRET`, `KIS_PAPER_ACCOUNT_NO` | Docker Compose 환경변수 |
| KB증권 | `KB_APP_KEY`, `KB_APP_SECRET` | Docker Compose 환경변수 |
| Alpaca | `ALPACA_API_KEY`, `ALPACA_SECRET_KEY` | Docker Compose 환경변수 |

- 모든 로컬 인증정보는 저장소 루트 `.env`만 사용한다. 별도 `*.key` 파일과 `/run/secrets` fallback은 없다.
- Key와 Secret은 반드시 한 쌍으로 설정하며 브라우저·로그·API 응답에 원문을 노출하지 않는다.

### 기동 전 체크리스트 (최초 한 번 수행)

1. `.env` 생성: `cp .env.example .env` 후 `SECRET_KEY`, DB 비밀번호를 변경한다.
2. `.env`에 필요한 브로커 키를 입력하고 권한을 제한한다.
   ```bash
   chmod 600 .env
   ```
3. Git 추적 여부 확인(출력이 비어야 정상):
   ```bash
   git ls-files | grep -E '\.key$|\.pem$|\.env$|^mcp/|^\.vscode/'
   ```
4. 기동·설정 상태 확인:
   ```bash
   docker compose up -d --build
   curl -s http://localhost:3333/api/broker-test/kis/status
   ```

### 환경변수 사용 시 주의

- `.env`의 값은 `docker-compose.yml`의 `python-backend.environment` 블록을 거쳐 컨테이너로 전달된다. 이 블록에 없는 변수는 `.env`에 적어도 무시된다.
- `KIS_PAPER_ACCOUNT_NO`는 `12345678-01`처럼 CANO와 상품코드를 하이픈으로 이어 한 값으로 적는다. 상품코드를 별도 변수로 넣는 방식은 지원하지 않는다.
- 백엔드는 항상 Testbed 도메인만 사용하므로 모의/실전 전환 변수는 없다. Alpaca도 Paper 도메인이 코드에 고정되어 있다.
- Docker 없이 `python app.py`로 직접 실행하면 `app.py`가 저장소 루트의 `.env`를 읽는다(이미 설정된 환경변수 우선).

### 호출 대상과 거래 ID (TR_ID)

| 웹앱 API | KIS Testbed 경로 | TR_ID |
|---|---|---|
| `GET /api/broker-test/kis/quote?symbol=005930` | `/uapi/domestic-stock/v1/quotations/inquire-price` | `FHKST01010100` |
| `GET /api/broker-test/kis/chart?symbol=005930` | `/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice` | `FHKST03010100` |
| `GET /api/broker-test/kis/orderbook?symbol=005930` | `/uapi/domestic-stock/v1/quotations/inquire-asking-price-exp-ccn` | `FHKST01010200` |
| `GET /api/broker-test/kis/index?code=0001` | `/uapi/domestic-stock/v1/quotations/inquire-index-price` (0001 코스피, 1001 코스닥) | `FHPUP02100000` |
| `GET /api/broker-test/kis/balance` | `/uapi/domestic-stock/v1/trading/inquire-balance` | `VTTC8434R` |
| `POST /api/broker-test/kis/order-flow-test` | `order-cash` → `order-rvsecncl`(정정) → `order-rvsecncl`(취소) | `VTTC0012U`, `VTTC0013U` |

- 도메인은 모의 `https://openapivts.koreainvestment.com:29443`으로 고정되어 있다. 실전 `https://openapi.koreainvestment.com:9443`은 코드에 없다.
- 모의 TR_ID는 `V`로, 실전은 `T`로 시작한다. 공식 예제를 볼 때 이 차이를 학습자에게 알려 준다.
- 주문 흐름 안전장치: 삼성전자 현재가의 90%(호가 단위 내림)를 지정가로 계산해 비시장성 매수 1주 → 한 호가 아래로 정정 → 전량 취소 순서다. 정정·취소가 실패하면 오늘 미체결을 조회해 남은 주문을 취소하고, 서버 락으로 동시 실행을 거부한다.

### 운영 제한·주의

- Testbed 토큰 발급은 분당 1회 제한이다. 서버가 토큰을 약 하루 캐시하므로 컨테이너를 자주 재시작하면 "토큰 발급 실패"가 날 수 있다.
- 시세는 3초 캐시된다. 버튼 연타·폴링을 금지시킨다.
- 장 운영 시간 외에는 모의 주문 접수가 거부될 수 있다. 오후 실습은 장중(09:00–15:30)에 맞춘다.

### 선택: KIS MCP (VS Code에서 자연어로 조회)

이 저장소는 MCP 서버를 직접 구현하지 않고 공식 저장소를 `mcp/open-trading-api`에 clone해서 쓴다(`/mcp/` 전체가 gitignore).

| 항목 | 내용 |
|---|---|
| 설치 | `git clone --depth 1 https://github.com/koreainvestment/open-trading-api.git mcp/open-trading-api` 후 `cd "mcp/open-trading-api/MCP/Kis Trading MCP" && uv sync` (Python 3.11+, uv 필요) |
| 인증정보 | 저장소 루트 `.env`의 `KIS_PAPER_APP_KEY`, `KIS_PAPER_APP_SECRET`, `KIS_PAPER_ACCOUNT_NO`를 재사용한다. |
| VS Code 설정 | `.vscode/mcp.json` (gitignore 대상). 계좌번호 앞 8자리는 `inputs`로 실행 시 입력받는다. |
| 공식 설정 파일 | `mcp/open-trading-api/kis_devlp.yaml`(`paper_app`, `paper_sec`, `my_paper_stock`, `my_prod`)은 이 저장소가 사용하지 않으며 값을 채우지 않는다. |

### 진행자 사전 점검 명령

```bash
# 키·토큰은 응답에 포함되지 않는다.
curl -s 'http://localhost:3333/api/broker-test/kis/quote?symbol=005930'
curl -s 'http://localhost:3333/api/broker-test/kis/index?code=0001'
curl -s 'http://localhost:3333/api/broker-test/kis/balance'   # account 설정 시
cd python-stock-backend && python kis_quote_test.py --symbol 005930
```
