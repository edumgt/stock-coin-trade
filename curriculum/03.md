# Alpaca Paper Trading 모듈 실습

## 과정 개요

- 대상: 미국주식 API와 Paper Trading 흐름을 배우려는 학습자
- 목표: Alpaca Paper 계정을 만들고 Paper Key를 안전하게 설정한 뒤, 계정·시세 조회와 보호된 Paper 주문→취소 흐름을 이해한다.
- 산출물: `.env` 설정 점검, Paper 계정 연결 기록, Paper 주문 흐름 점검 결과

> Paper Trading은 실제 거래소에 주문을 전송하지 않는 시뮬레이션이다. 그러나 주문 상태를 만들 수 있으므로, 테스트도 로그인·명시적 확인·취소 확인을 거친다.

## 오전 — Alpaca 가입과 Paper Key 준비 (3시간)

| 시간 | 학습자 활동 | 진행자/조교 역할 | 완료 기준 |
|---|---|---|---|
| 09:00–09:30 | Alpaca Live와 Paper 계정·키·도메인의 차이를 구분한다. | Live 키를 사용하지 않는 원칙을 설명한다. | Paper 환경만 선택한다. |
| 09:30–10:15 | Alpaca 대시보드에서 가입·이메일 확인 후 Paper 계정을 생성한다. | 국가·계정 조건은 공식 화면을 우선하도록 안내한다. | Paper 계정이 대시보드에 보인다. |
| 10:25–11:10 | Paper 계정의 API Keys에서 Key·Secret을 발급한다. | Secret은 재표시되지 않을 수 있음을 안내한다. | Paper Key 한 쌍을 보관한다. |
| 11:10–12:00 | `.env`를 설정하고 Git 제외를 확인한다. | 값이 아닌 파일 형식만 확인한다. | 서버에서 Paper Key를 읽을 수 있다. |


### 안전한 주문 흐름의 기능

1. 로그인과 체크 확인이 있어야 요청할 수 있다.
2. Paper 엔드포인트만 사용한다.
3. AAPL 1주와 고정된 낮은 지정가로 비시장성 주문을 시도한다.
4. 가격 안전 조건을 만족할 때만 요청한다.
5. 주문 식별자·Secret·Token은 화면에 노출하지 않는다.
6. 주문 직후 취소를 요청하며, 취소 실패 시 대시보드에서 미체결 주문을 확인한다.

### 역할 분담

- 계정 담당: Paper/Live 분리와 Key 발급 상태를 확인한다.
- 데이터 담당: `/account`, `/positions`, `/orders`, `/clock`, 시장 데이터 결과를 해석한다.
- 주문 담당: 확인 문구·수량·가격 제한·자동 취소가 유지되는지 점검한다.
- 감사 담당: 주문 응답만 보지 않고 주문 내역·포지션으로 후속 대사를 확인한다.

### 연계 실습 — TradingView 학습과 Pine 사전 점검 (60분)

Alpaca Paper 주문은 신호를 확인한 뒤에만 연습한다. Pine Script 계산과 Alpaca 주문은 직접 연결하지 않으며, 각각 분석과 Paper 주문의 역할을 분리한다.

| 기능 | 구현·사용 순서 | 역할 | 확인 항목 |
|---|---|---|---|
| TradingView(Pine) 학습 | `/learning/tradingview-pine.html` | 전략 설계 담당 | 지표(`indicator`)와 가상 주문 전략(`strategy`)의 차이를 설명한다. |
| Pine 간단 테스트 | `/pine-script-lab.html`에서 MA·RSI 예제를 수정 | 조건 검증 담당 | 기간을 하나만 변경해 신호 수·단순 수익률·MDD 변화만 비교한다. |
| Pine 전략 모의주문 | `/trade/pine.html` | 앱 모의주문 담당 | 이 웹앱의 모의주문과 Alpaca Paper 주문은 서로 다른 장부임을 확인한다. |
| 최종 검증 | TradingView Pine Editor | 백테스트 검토 담당 | 실제 종목·시간봉·수수료·슬리피지를 넣은 Strategy Report로 재검증한다. |

**구현 관점:** Pine 간단 테스트는 제한된 문법의 교육용 계산기다. 웹훅·API Key·계좌 정보를 Pine 코드 또는 브라우저에 넣지 않으며, 자동매매 연결은 주문 중복 방지·손실 한도·감사 로그가 갖춰진 별도 서버에서만 검토한다.

## 준비·설정 상세 (이 저장소 기준)

키 저장 위치와 기동 전 체크리스트는 `01.md`의 "준비·설정 상세"를 따른다. Alpaca는 `.env`의 `ALPACA_API_KEY`/`ALPACA_SECRET_KEY`만 사용한다. Paper 도메인은 코드에 고정되어 있어 Live로 전환되는 설정은 없다.

### 사전 가입·발급 절차 (오전 실습 상세)

| 순서 | 할 일 | 어디서 | 결과물 |
|---|---|---|---|
| 1 | 이메일 가입 후 이메일 확인 | <https://app.alpaca.markets/signup> | Alpaca 계정 |
| 2 | 대시보드 좌측 상단 계정 선택기에서 **Paper Trading** 선택/생성 | <https://app.alpaca.markets/account/login> | Paper 계정 |
| 3 | Home → **API Keys**에서 Paper 키 생성. Secret은 재표시되지 않을 수 있다. | 대시보드 | Paper Key·Secret |
| 4 | `.env` 작성 (위 형식), 권한 600 | 저장소 루트 | 파일 준비 완료 |

- 앱이 사용하는 변수명은 `ALPACA_API_KEY`/`ALPACA_SECRET_KEY`로 고정한다.
- Paper 전용 계정은 거주 국가와 무관하게 별도 심사 없이 만들 수 있다. Live 계정 승인·세금 서류는 과정 범위 밖이다.
- Paper 키를 Live 도메인에, Live 키를 Paper 도메인에 넣으면 401이 난다. 코드는 Paper 도메인 고정이라 Live 키를 넣어도 Live 주문은 나가지 않는다.
- 저장소 루트의 `ALPACA_REFERENCE_KEY`는 Alpaca 키 형식이 아닌 별도 식별자이며 코드가 읽지 않는다.

### 호출 대상

| 웹앱 API | Alpaca 경로 | 헤더 |
|---|---|---|
| `GET /api/alpaca-test/paper/account` | `https://paper-api.alpaca.markets/v2/account` | `APCA-API-KEY-ID`, `APCA-API-SECRET-KEY` |
| `GET /api/alpaca-test/paper/positions` | `/v2/positions` | 동일 |
| `GET /api/alpaca-test/paper/orders` | `/v2/orders?status=all&limit=10` | 동일 |
| `GET /api/alpaca-test/market/clock` | `/v2/clock` | 동일 |
| `GET /api/alpaca-test/market/quote?symbol=AAPL` | `https://data.alpaca.markets/v2/stocks/AAPL/quotes/latest`, `.../trades/latest` | 동일 |
| `POST /api/alpaca-test/paper/order-flow-test` | `POST /v2/orders` → `DELETE /v2/orders/{id}` | 동일 + 로그인 세션 |

- 주문 흐름 안전장치: AAPL 매도호가가 $2 초과일 때만 1주 $1.00 지정가(비시장성) 매수 후 즉시 취소한다. 취소 실패 시 대시보드 확인을 안내하고, 서버 락으로 중복 실행을 막는다.
- 시장 데이터는 무료 플랜의 IEX 피드 기준이라 장외 시간에는 마지막 값이 오래된 것일 수 있다. "Clock과 시세의 차이" 토의에 활용한다.
- 취소 응답이 204(본문 없음)일 수 있어 코드가 이를 성공으로 처리한다.
