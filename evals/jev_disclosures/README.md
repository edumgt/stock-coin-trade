# DART 공시 판정 평가 (규칙 vs 규칙 + 외부 판정 모델)

공시 레이더(`src/deskjev/disclosures.py`)가 DART 공시 제목(`report_nm`)을 교육용 유형과 "매매 불가 위험"으로 맞게 나누는지 잰다. 규칙만 쓸 때와 규칙이 못 정한 것에 판정 모델을 더할 때를 같은 사례로 나란히 재서, 판정 모델이 실제로 보태는 만큼만 주장한다.

> **라벨은 에이전트(Claude)가 달았다. 노아 검수 전이다.** 규칙 표를 쓴 쪽과 라벨을 단 쪽이 같다. 그래서 정해진 서식(`fixed`)에서 규칙이 100%인 것은 독립 측정이 아니다. 뜻이 있는 숫자는 규칙이 비우는 `free`·`risk_open`과 따로 둔 `heldout.jsonl`이다.

## 사례

| 파일 | 건수 | 만든 방법 |
|---|---|---|
| `cases.jsonl` | 285 | 2026-09-17·18·21·22·23 DART 목록(상장사 1,931건, 서로 다른 제목 354개)에서 층화 표본. 부제가 붙었거나 규칙이 비우는 제목은 모두, 나머지 서식은 서식마다 최대 2건(정정 우선) |
| `heldout.jsonl` | 55 | 2026-09-10·11·14·15·16 목록에서 `cases.jsonl`에 없고 규칙이 비우는 제목 전부. **v2 문구를 고치기 전에** 라벨을 달고 파일 해시(sha1 `19fc11b…`)를 남겼다 |

모든 `report_nm`은 실제 DART 제목이다. 층(`stratum`): `fixed` 규칙이 유형·위험을 다 정함(210), `free` 규칙이 유형을 못 정함(48), `risk_open` 유형은 정했지만 위험은 부제에 달림(조회공시·소송, 27). 위험 정답이 참인 사례는 43건(held-out 13건).

필드: `id`(접수번호), `rcept_dt`, `report_nm`, `rm`, `corp_cls`, `kind`(정답 유형), `kind_alt`(둘 다 맞다고 본 유형), `risk`(정답 위험), `stratum`.

헷갈리는 쌍: 임원ㆍ주요주주특정증권등소유상황보고서 vs 최대주주변경, 불성실공시법인지정 vs 지정예고, 주권매매거래정지 vs 정지해제 vs 정지해제(정리매매 개시), 파산신청 vs 파산신청기각, 실질심사 사유 발생 vs 절차 중단, 본사 vs 자회사 사건, [기재정정]이 붙은 것. 적자전환·흑자전환처럼 실적 방향이 제목에 드러난 공시는 이 10영업일 표본에 없었다(영업(잠정)실적 서식은 분기 실적 발표 시기에 몰린다).

### 라벨 기준

- 위험(참): 거래정지·정지기간 변경, 상장폐지 사유·우려·정리매매, 관리종목(우려), 상장폐지 심사 절차(실질심사, 기업심사위원회·시장위원회·상장공시위원회, 개선계획), 회생·파산·부도, 횡령·배임 혐의, 불성실공시법인 **지정**(하루 매매정지), 회계처리기준 위반 검찰고발.
- 위험(거짓): 정지 해제(정리매매 개시는 제외), 채권자 파산신청 기각·취하, 심사 절차 중단, 지정**예고**, 자회사·종속회사의 사건, 당일 정지·해제(매매거래정지및정지해제).
- 판단이 갈리는 것(라벨은 그대로 두고 적어 둔다): 주식 병합·SPAC 합병 때문인 기술적 거래정지는 "사고팔 수 없음"이라 참. 회생절차 **개시신청 기각**은 채권자 파산신청 기각과 달리 회사에 나쁜 소식이라 참. 회생계획인가는 회생이 이어진다고 보아 참. 대출원리금 연체는 부도가 아니라 거짓.

## 실행

```bash
# 오프라인·무료. oracle이 100%가 아니면 채점기나 사례가 틀렸다(단위 테스트가 두 세트 모두 확인한다. 결과 파일은 남기지 않는다).
PYTHONPATH=src:python-stock-backend python -m deskjev.eval_disclosures --mode oracle
PYTHONPATH=src:python-stock-backend python -m deskjev.eval_disclosures --mode rules
# 실제 판정 모델(과금). 비용 상한 없이는 실행하지 않는다. 285건 중 75건만 판정 모델을 부른다.
PYTHONPATH=src:python-stock-backend TYPESAFE_API_KEY=... python -m deskjev.eval_disclosures --mode live --max-usd 1
# 따로 둔 사례
PYTHONPATH=src:python-stock-backend TYPESAFE_API_KEY=... python -m deskjev.eval_disclosures --mode live --max-usd 1 \
  --cases evals/jev_disclosures/heldout.jsonl --out evals/jev_disclosures/results/live-heldout.json
```

이 Mac에서는 `.venv` 파이썬이 네이티브 확장 import에서 멈춰, CI와 같은 이미지(`sct-test:dev`)로 돌렸다.

## 결과 (판정 모델 버전 1.13.0, 2026-09-26)

`results/`에는 최종 4개(`rules.json`, `live.json`, `rules-heldout.json`, `live-heldout.json`)만 남겼다. v1·v2 중간 결과와 oracle 결과는 아래 표의 수치로만 남긴다(PM 검수 2026-09-26).

| 결과(파일) | 사례 | 유형 정확도 | free 유형 | 위험 재현율 | 위험 정밀도 | 비고 |
|---|---|---|---|---|---|---|
| 규칙만, v1 낱말 | 285 | 0.930 | 0.583 | 0.791 | 1.000 | 중간 결과(파일은 뺐다) |
| 규칙+판정 모델, v1 위험 질문 | 285 | 0.989 | 0.938 | 0.791 | 1.000 | 중간 결과 |
| 규칙만, v1 낱말 (held-out) | 55 | 0.618 | 0.533 | 0.538 | 1.000 | 중간 결과 |
| 규칙+판정 모델, v1 (held-out) | 55 | 0.891 | 0.867 | 0.462 | 1.000 | 위험은 낱말 규칙보다 못했다 |

판정 모델이 정한 부분만: 유형을 판정 모델이 정한 48건(held-out 45건)의 정확도 0.938(0.867), ECE 0.056(0.076). 위험 Noul의 ECE 0.134(0.080). 지연(판정 모델을 부른 사례, 이 Mac → 외부 서비스, nearest-rank) p50 202ms, p95 274ms. 호출 한 번 입력은 약 1,780토큰(유형 선택지 20개의 설명 포함).

### 무엇을 말할 수 있나

- **유형: 판정 모델이 보탠다.** 규칙이 못 정하는 자유 서식의 유형 정확도가 held-out에서 0.533 → 0.867, held-out 전체로는 0.618 → 0.891. 목표 90%는 285건 세트(0.989)에서 넘고 held-out(0.891)에서는 조금 모자란다.
- **위험: 판정 모델만으로는 낱말 규칙보다 낫지 않다.** v1 질문은 기업심사위원회·개선계획서 같은 상장폐지 심사 용어를 위험으로 보지 않았다(확률 0.12~0.36). 질문에 절차를 설명한 v2도 held-out 재현율이 0.615로 낱말 규칙과 같았다. 둘이 놓치는 공시가 달라 "둘 중 하나라도"로 합쳤고 held-out 재현율 0.692, 정밀도 1.000이다. 이 합치는 방식은 held-out 결과를 보고 골랐으므로 **최종 정책의 깨끗한 held-out 수치는 없다.**
- 하루 상장사 공시 대부분은 규칙이 정한다: 2026-09-23 상장사 420건 중 판정 모델이 필요한 것은 23건.

### 남은 오류 (`live.json`, `live-heldout.json`의 `summary.errors`)

- 회계처리기준 위반 검찰고발(3건): 유형을 소송·불성실공시로 보고 위험 확률은 0.24~0.29. 라벨은 기타·위험 참.
- 상장·공시위원회 결과 / 상장공시위원회 개최기한 연장: 유형을 기타로 본다(라벨은 상장폐지·관리종목). 위험은 낱말이 잡는다.
- 관계인집회 기일 결정(회생 절차 용어): 유형을 주주총회로, 위험을 0.04로 본다.
- 회생절차 개시신청 기각: 위험 0.32. 낱말 규칙은 '기각'이라 풀렸다고 본다. 둘 다 놓친다.
- 장래사업ㆍ경영계획(공정공시) → 정기보고서, 자기사채(8CB) 소각 → 자기주식: 위험은 맞고 유형이 틀렸다.
- 소송등의판결ㆍ결정(부제 없음): 위험 확률이 0.47(v2)·0.50(최종)으로 경계에 걸려 최종 실행에서 위험으로 표시됐다. 같은 문구로 두 번 돌린 확률 차이는 최대 0.04, 평균 0.009다. 임계값은 사후에 바꾸지 않았다.

### 규칙 표 수정 (라벨을 달며 찾은 순서 오류)

"기업가치제고계획(…고배당기업…)"이 배당으로, "기업인수목적회사의예치ㆍ신탁계약"이 자기주식으로, "유상증자최종발행가액확정(…소액공모)"이 발행 서류로, "증권발행결과(…제3자배정 유상증자)"가 유상증자로, "해산사유발생(자회사의 주요경영사항)"이 위험 참으로 나왔다. 줄 순서와 자회사 규칙으로 고쳤고 회귀 테스트가 있다(`tests/unit/test_disclosures.py::test_rule_order_fixes_found_while_labelling`).

## 하루 호출·비용 추정

실측(2026-09-23 목록 전체 683건, 상장사 420건, 규칙이 비운 공시 23건)으로 어림한다. 그날 목록 파일은 계획 승인 범위(평가용 약 200건)를 넘고 DART 약관이 미확인이라 저장소에 두지 않는다. PM이 로컬 스택에서 같은 날을 수집했을 때도 `jev_calls` 23이었다. → 하루 판정 모델 약 23회, 입력 약 41,000토큰. 캐시가 없으므로 같은 제목도 매번 과금된다.
